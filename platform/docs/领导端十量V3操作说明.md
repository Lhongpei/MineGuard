# 领导端十量 V3 操作说明

本页面向监管领导和只读查看人员。领导端的目标是用几分钟回答“哪些矿需要优先核查、
为什么、下一步调什么原始凭证”，不要求领导填报、改算法或处理技术配置。

## 每天三步

1. 看总览顶部：应报矿数、已报矿数、风险矿数和数据不足矿数。数据不足不是正常，先
   安排补数或核对来源。
2. 看“重点关注”：优先处理高严重度、连续多日、跨多类证据且来源独立的线索；单一
   历史偏离只作为复核提示。
3. 点进一座矿：查看受影响日期、指标、证据方法和建议核查材料，交办企业调阅原始
   台账。企业文字回复只会留痕，不会自动消除风险。

需要会议展示时使用“大屏展示”；需要检索具体矿井、月份或指标时再进入专业列表。
领导账号始终只读，页面不存在替企业新增、修改、确认、删除或关闭风险的权限。

## 十量怎样看

页面按三组展示：

- 安全生产支撑：风量、电量、火工品量、入井人员量；
- 生产煤流：产量、开采量、销售量、运输量、洗煤量；
- 经营票据：开票量。

底层共有 11 个原子字段，因为火工品量分为 `detonators_count`（雷管发数）和
`explosives_kg`（炸药质量），两者不能相加。其余字段为
`ventilation_m3_min`、`electricity_kwh`、`mine_entry_persons`、`production_t`、
`extraction_t`、`sales_t`、`transport_t`、`wash_feed_t`、
`invoiced_quantity_t`。

销售、运输和开票不是同一个量：销售是销售交付实物量，运输是出矿/外运净吨数，
开票是正常/蓝字发票对应实物吨数。三者可能因在途、签收和跨期开票存在合法时差，
不能按同一天简单等值，也不能在物料平衡里重复扣减。开票主量永远非负；红票、退票、
作废、折让和退货是辅助明细，净额另算。

## 状态怎样理解

| 页面状态 | 领导应怎样理解 | 建议动作 |
| --- | --- | --- |
| `risk` | 至少一组可核验关系或多源证据形成技术冲突 | 调原始凭证，指定复核人和时限 |
| `insufficient_data` | 十量主字段、必需班次或当前已启用分析证据不足 | 先补数据，不能当成正常 |
| `normal_candidate` | 当前证据内未发现达到门槛的冲突 | 可抽查，不能等同合法/安全认定 |
| `Legacy 5/10` | 只收到五量 V2 历史字段 | 只读参考，不补造新增五项 |

历史基线只使用报告截止日前、已正式准入的本矿数据；同类矿只显示匿名区间且至少满足
样本门槛。L1 求解器用于联合协调观测和参考带，MCS 用于定位最少需放宽的冲突组；它们
不预测所谓“真实产量”，历史相关性也不是物理定律。

本版主报文尚不包含库存边界、洗后产出/损耗和逐批运输—开票日期。页面显示的是主量
确定性、同期间软关系和历史/同类矿证据，不代表平台已经完成收发存、洗选物料平衡或
逐批账龄核验；这些资料仍应在交办后调阅，不能因页面没有对应线索就推定不存在问题。

## 交办时至少写清楚

- 矿井、统计窗口和受影响日期；
- 指标原子字段及页面显示单位；
- 需要调阅的设备读数、日报、班次、地磅、运单、洗选、销售或发票凭证；
- 回复期限和负责人员；
- 如果涉及开票，要求同时提供正常发票和红票/退票等辅助明细，不能只报一个净数。
