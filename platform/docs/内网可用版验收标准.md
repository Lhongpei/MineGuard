# MineGuard 内网可用版验收标准

## 1. 本次“完备可用”的定义

本次交付目标是：在单机或受控内网环境中，可接入经过登记的真实数据源，
完成数据验签、版本化分析、任务运行、领导查看、人工核查、双人复核、
证据导出、审计校验、备份和恢复。

系统只生成技术核查线索，不自动形成违法事实、责任或处罚结论。

以下事项依赖部署单位提供外部基础设施，代码只能提供适配接口和强制门槛：

- 组织统一身份平台及真实人员、机构、矿井数据域；
- 设备侧签名密钥、密钥轮换制度和硬件密钥保护；
- HTTPS 证书、内网域名、反向代理和网络访问控制；
- PostgreSQL 高可用、对象锁/WORM 存储、异地备份介质；
- 原始视频、设备日志、业务凭证及其授权访问接口；
- 正式执法流程、证据规则、数据保留期限和安全测评结论。

未接通这些外部条件时，界面和导出材料必须继续标记为“影子运行/技术线索”。

本标准所称“全证据闭环”仅适用于通过 `/v1/ingest/production*` 可信入口完成的
正式五量分析。`aggregate`、`flow`、`temporal` CLI 及
`/v1/analyze/aggregation`、`/v1/analyze/flow`、
`/v1/analyze/temporal` 管理员接口属于算法沙箱试算，用于配置验证和离线复现；
它们不会自动生成正式案件、办理事件或证据包，不纳入全证据闭环验收。若要转为
正式业务能力，必须另行完成来源治理、版本审批、持久化、权限和案件流程接入。

## 2. 功能验收

- 按应报矿井名单展示实报、缺报和覆盖率，缺失值不得解释为零。
- 来源、容差、可靠性、根来源组和分析参数只能由服务端版本化配置决定。
- 数据必须校验来源、单位、序号、修订号、业务时间、载荷哈希和签名。
- 支持批量异步任务、窗口失败隔离、幂等、取消、重放、终态归档/恢复和重启恢复。
- 每次通过可信入口提交的正式五量分析保留输入快照、配置版本、代码版本、结果
  哈希和历史版本；算法沙箱试算由操作者另行归档输入、输出和运行时版本清单。
- 技术状态、复核优先级和办理状态独立表达。
- 核查事项支持分派、补数、说明、结论撤回、双人复核、关闭、重开和关闭后
  归档/恢复。
- 分析批次支持填写原因后作废/恢复，并可集中隔离历史演示批次；已作废批次默认
  不进入正式总览、趋势、案件和算法校准统计。
- 支持辖区趋势、重复线索、处理时长、有效线索率和积压量统计。
- 支持生成可离线校验的证据包，任何内容变化必须导致校验失败。
- 支持备份、恢复演练、健康检查和安全审计导出。

## 3. 安全验收

- 默认启用登录，不存在生产环境匿名写接口。
- 密码不以明文或可逆形式存储；会话令牌只存摘要。
- 所有状态变更校验 CSRF；Cookie 使用 HttpOnly 和 SameSite。
- 角色权限和矿井数据域同时生效，越域访问返回拒绝且写入审计。
- 用户禁用、退出和全量撤销后，会话立即失效。
- 人员身份在非授权视图中脱敏，下载和打印继续执行权限检查。
- 登录失败限速；请求大小、查询参数、静态路径和错误回显均有边界。
- 本地哈希链不得表述为数字签名、可信时间戳或不可篡改存储。
- 证据包、追加式审计和备份不得从业务前端硬删除；达到留存期限后的销毁必须按
  部署单位批准的离线运维流程执行并留痕。

## 4. 运维验收

- 默认数据目录不进入代码仓库，密钥不得写入代码或导出包。
- `/health` 仅表示进程存活；就绪检查应覆盖数据库、任务线程和关键配置。
- 备份包含数据库、配置版本和证据清单；恢复后重新进行哈希校验。
- 权限审计以结构化事件写入用户库；反向代理访问日志按部署单位标准结构化并与
  应用审计时间关联，二者都不得写密码、会话令牌、签名密钥或完整人员身份。
- 同一快照、配置和代码版本重放时，核心结果哈希保持一致。
- 发布归档保留 `constraints.txt` 和运行时版本清单，依赖升级后重新执行算法、
  迁移、接口和备份恢复验收。

## 5. 发布级别

1. **本地演示**：仅脱敏示例，可关闭认证。
2. **内网影子运行**：必须启用认证、可信来源、服务端配置、备份和审计。
3. **正式业务辅助**：还必须接通统一身份、生产数据库、对象锁存储、设备密钥、
   HTTPS、监控告警并通过安全与业务验收。
4. **执法使用**：不由软件单方面决定，必须另行完成法律、证据和行政流程授权。
