# 企业端分级账号操作手册

## 1. 适用范围

本手册面向使用企业可信数据填报智能体的领导、查看人员、填报经办人、复核确认人、
报送人员和系统管理员。内容以当前系统实际实现为准，适用于同源网页端的草稿填报、
煤炭智能任务、煤炭业务对话、人工确认和监管报送流程。

系统没有用“领导”“经办人”“管理员”等岗位名称直接决定权限。登录账号的
`role` 只用于页面展示和确认留痕，真正的操作能力由以下六项权限独立决定：

| 权限 | 页面中的业务含义 | 主要能力 |
| --- | --- | --- |
| `read` | 查看与分析 | 查看草稿、问题、预检、回执、审计、工具目录；发起/取消/重试本人的 V2 只读体检和旧版智能任务；煤炭业务对话 |
| `write` | 填报与修改 | 新建、编辑、导入、移除尚未确认的草稿；使用模型提取建议；批准智能任务中的草稿补丁；管理 V2 计划并提出记忆/技能 |
| `confirm` | 复核与企业确认 | 以当前本人账号逐项记录观测核对并确认当前修订 |
| `submit` | 正式报送 | 将已经有效确认的当前修订版本提交监管平台 |
| `governance_review` | 业务记忆治理 | 审批或拒绝记忆提案，撤销有效记忆 |
| `skill_admin` | 只读技能目录治理 | 审批或拒绝技能提案，停用有效技能目录版本 |

权限可以组合，不是必须逐级包含。为保证网页端能够正常使用，正式账号通常都应包含
`read`，再按职责增加其他权限。只配置 `write`、`confirm` 或 `submit` 而不配置
`read` 虽不被账号配置格式直接禁止，但网页端无法完成前置查看流程，不建议这样配置。

## 2. 如何判断当前账号级别

登录后应以页面显示的账号、岗位、权限提示和按钮状态为准，不要只看岗位名称。前端
应读取 `/api/v1/auth/me` 返回的以下字段判断操作说明：

- `permissions`：当前账号实际拥有的权限集合；
- `must_change_password`：是否仍为待换密账号；
- `temporary_demo`：是否为本机临时演示账号；
- `actor_id`、`name`、`role`：用于身份展示和审计，不用于扩大权限。

推荐按能力组合显示以下账号类型。它们是操作说明分组，不是后端新增的固定角色：

| 前端操作说明标题 | 推荐权限组合 | 可以做 | 不可以做 |
| --- | --- | --- | --- |
| 监督查看账号 | `read` | 查看草稿、回执和审计；运行、取消或重试本人 V2 只读体检；进行煤炭业务对话 | 新建、编辑、删除、管理计划、提出治理提案、正式核对、确认、提交 |
| 填报经办账号 | `read, write` | 完成草稿创建、编辑、导入、预检和智能建议采纳；管理本人 V2 计划并提出记忆/技能；批准本人旧版任务中的单项草稿补丁 | 留下正式逐项核对记录、治理审批、企业确认、监管提交 |
| 复核确认账号 | `read, confirm` | 查看并预检；本人逐项核对全部观测；完成账号点击确认 | 修改数据、创建计划或提案、批准草稿补丁、治理审批、提交监管平台 |
| 记忆治理账号 | `read, governance_review` | 核对记忆来源，审批/拒绝记忆提案，撤销有效记忆 | 修改或确认草稿、治理技能、监管提交 |
| 技能治理账号 | `read, skill_admin` | 核对只读技能边界，审批/拒绝技能提案，停用目录版本 | 修改或确认草稿、治理记忆、监管提交 |
| 报送执行账号 | `read, submit` | 查看已确认内容和提交门禁；提交有效确认版本；查看回执 | 修改草稿、替别人完成核对或确认 |
| 经办兼确认账号 | `read, write, confirm` | 填报、逐项复核并确认当前版本 | 监管提交 |
| 经办兼报送账号 | `read, write, submit` | 准备阶段可以填报；可提交其他确认人已确认且此后未修改的版本 | 逐项复核和企业确认 |
| 确认与报送账号 | `read, confirm, submit` | 逐项复核、确认并提交当前版本 | 修改数据或批准草稿补丁 |
| 全权限账号 | `read, write, confirm, submit, governance_review, skill_admin` | 在职责允许时完成填报、确认、报送和两类治理 | 仍不能让 AI 代替人工确认，也不能绕过四眼审批、预检、凭证和平台门禁 |
| 自定义协作账号 | 其他组合；缺少 `read` 时网页流程安全降级 | 在同一说明中按实际权限叠加能力和交接项 | 不能把岗位名称或“最高权限”当成完整流程能力 |
| 本机演示账号/待换密账号 | 任意已配置权限，同时有凭据锁定标记 | 按实际 `read/write` 等未锁权限体验相应功能 | 正式逐项核对、企业确认和监管提交 |
| 权限配置异常 | 无可识别权限 | 查看配置错误提示 | 开展任何业务操作 |

非典型组合不会显示多张互相冲突的卡片，而是在同一份说明中展示一个概括标题、六项
权限徽标，并叠加建议步骤、授权能力和交接事项。例如，`read, write, submit` 在准备
阶段可以编辑；但其他确认人完成确认后不得再次修改，只能提交该已确认且此后未修改
的版本。`read, confirm, submit` 可以复核和提交，但遇到数据错误时必须退回具有
`write` 权限的经办人修改。

### 2.1 临时演示账号

未配置企业用户且服务只监听回环地址时，系统会启用：

- 账号：`demo`
- 默认密码：`123123123`
- 有效权限：`read, write`
- 标记：`temporary_demo=true`、`must_change_password=true`

该账号只用于本机演示。后端会强制禁止它执行逐项正式核对、人工确认和监管提交；
即使误给待换密账号配置了 `confirm`、`submit`、`governance_review` 或
`skill_admin`，这些高权限操作仍会被拒绝。非回环地址
不会自动创建 demo 账号。

当前系统没有网页内自助改密功能。转为正式账号时，管理员必须用
`enterprise-agent hash-password` 生成新密码摘要，在企业密钥系统中更新
`ENTERPRISE_AGENT_USERS_JSON`，将 `must_change_password` 设为 `false`，然后重启
服务。不得把明文密码写入用户 JSON、仓库或启动脚本。

### 2.2 快捷填报与专业工具

网页默认进入“快捷填报”，只显示综合可用状态、草稿列表和当前下一项任务。系统根据
草稿完整度与当前账号实际权限给出提示：经办人看到填写和导入任务，确认人看到逐项
复核与企业确认，报送人员看到提交门禁，只读人员只看到状态与转交说明。岗位名称不会
扩大权限。

存在未提交草稿时，首页主按钮会优先继续最近草稿；确需另报时再点击“新建另一份”。
希望减少手工录入时，可点击“让 Agent 从材料自动填入”：页面会复用最近未提交草稿，
没有草稿时先创建一份，然后直接进入来源导入。符合合同的 JSON、CSV 字段会确定性
写入草稿并记录来源；自由文字与历史推断只生成候选建议，不能直接变成已核实事实。
“专业工具”用于煤炭智能任务、煤炭业务对话、详细运行状态和高级草稿操作。模式切换
不调用业务接口、不改变草稿或当前步骤，也不改变任何权限；刷新页面后默认回到快捷
填报。

快捷填报的当前任务卡直接提供“移除这份草稿”。该操作只适用于拥有 `write` 权限且
尚未人工确认的草稿，必须输入“移除”二次确认。移除是带审计的软删除：普通工作列表
不再显示，但数据库和审计链仍保留；已经确认、正在提交或已提交的记录不能移除，
绑定的智能体任务和启用计划也应先取消或停用。

### 2.3 智能体任务中心

页面顶部“智能体任务中心”是煤炭 Agent V2 的统一入口。它与“煤炭智能任务”
（可由模型规划工具的旧版 Harness）不是同一套任务记录。

任务中心当前提供三组页面：

1. “任务总览”：选择当前草稿，运行一次 `daily_coal_health`，先看负责人摘要，
   再按需展开来源、时序、物理和历史四个专家以及反方核验步骤；
2. “定时任务”：由 `write` 账号为当前草稿创建每日固定时间或按间隔执行的计划，
   并可立即运行、启停或软删除；
3. “记忆与技能治理”：由 `write` 账号提出记忆或技能；记忆由有效
   `governance_review` 账号审批，技能由有效 `skill_admin` 账号审批。

快捷模式始终回到任务总览，适合领导只看“需关注、执行中、今日完成”和易懂结论。
计划和治理入口放在专业模式。事件计划和事件发送已提供 API，但当前网页没有配置
入口。

任务状态应按下表理解：

| 页面状态 | 后端状态 | 处理方式 |
| --- | --- | --- |
| 等待执行 | `queued` | 已落库，可关闭页面等待；必要时取消 |
| 正在检查 | `running` | 四专家或摘要正在执行；取消会在只读步骤边界生效 |
| 需要关注 | `blocked` | 修复草稿不可用等条件后重试 |
| 已完成 | `succeeded` | 先读负责人摘要，再核对证据 |
| 执行失败 | `failed` | 查看失败步骤；排查后重试 |
| 已取消 | `cancelled` | 不形成新的完整体检结论，保留留痕 |

浏览器关闭不等于取消。服务重启后，未结束的 V2 只读任务会从 SQLite 恢复；
已经运行的步骤记录为中断，新尝试重新读取当前草稿完整复算。旧尝试不会被覆盖。

任务中心的负责人摘要不修改草稿，也不代表预检、企业确认或监管提交已经完成。
任何异常仍须回到原始凭证和现场业务核对。

## 3. 各类账号标准操作

### 3.1 查看人员或领导

1. 登录后先确认页面右上角的姓名、岗位，以及工作区的“监督查看账号/没有编辑权限”
   提示。
2. 在草稿列表中按“全部、未提交、已提交”查看填报状态。
3. 打开草稿，重点查看统计窗口、工况、来源、预检结果、最终确认身份、提交记录、
   平台回执和审计完整性。逐项核对接口按当前登录账号返回，普通查看账号不能据此
   查看其他确认人的未完成复核进度。
4. 如需快速判断数据情况，点击“智能体任务中心”，对当前草稿运行“每日煤炭
   体检”。先看负责人摘要和关注级别，需要时再展开四专家与反方复核步骤。
5. 如需更灵活的单项工具规划，切换到“专业工具”，使用旧版“煤炭智能任务”中的
   全面体检、异常与凭证、历史趋势、来源核验等模板。不要把两套任务编号混用。
6. 如需连续追问，可在“专业工具”中进入“煤炭业务对话”。分析本矿、本期或当前
   草稿数据时，应绑定对应草稿；询问通识或公开新闻时可以不绑定。
7. 发现问题后记录草稿编号、任务绑定的草稿修订号、关注级别和具体字段，交由有
   相应权限的人员处理。

只读人员可以发起、查看、取消或重试本人的 V2 任务，也可以使用旧版只读智能任务，
但不能创建定时计划、提出治理提案或批准会修改草稿的工具动作。只读人员也不能通过
对话或任务要求 AI 代为修改、确认或报送。

### 3.2 填报经办人

1. 首页若提示未完成草稿，优先点击“继续未完成填报”；没有对应草稿时再点击
   “新建填报”。填写企业、矿井、统计起止时间、配置版本和实际工况，并导入监管事件
   快照；即使查询结果为空，也必须导入专用空结果快照。已有 ERP、MES、地磅或化验
   导出文件时，也可直接点击“让 Agent 从材料自动填入”。
2. 导入来源材料：
   - JSON、CSV 走确定性导入并自动填写合同内字段；
   - 文字材料可由已配置模型生成候选建议，但不会自动采纳；
   - 监管事件代码必须走专用事件快照导入，手填空数组不能冒充权威查询结果。
3. 核对来源名称、来源系统、文件名和真实性声明。不要为通过校验临时编造来源。
4. 查看每项候选数字、来源位置和提取可信度。模型建议不会自动写入，只有点击采用或
   手工编辑后才进入草稿。
   专业工具中的“确认本页高可信度项”只处理当前分页，不会跨页确认；快捷填报默认
   隐藏该批量入口，应逐项查看来源后核对。
5. 回答缺项追问并运行提交前预检。阻断问题必须修正；“需说明”应结合原始材料处理。
6. 可运行煤炭智能任务辅助发现煤流、库存、时序、历史、煤质和来源问题。若任务提出
   `draft_patch`，必须逐项核对工具名称、字段、修改前后值和参数摘要后再批准。
7. 可在任务中心为当前草稿设置每日或间隔体检，也可提出业务记忆/技能提案。计划
   只绑定当前这份草稿，不会自动选择下一期新草稿；提案在审批前不会影响判断。
8. 完成后把草稿编号、当前修订号和最近一次 V2 负责人摘要交给具有 `confirm`
   权限的确认人。

经办人手工修改观测值、单位、时间、来源编号或其他受签业务字段，会使原来源摘要和
网关签名失效。此时不能自行补签，必须从来源系统重新导出并签发后再导入。
误建且尚未人工确认的草稿可在快捷任务卡点击“移除这份草稿”；不要用该入口替代业务
更正或撤回流程，已经确认或取得平台回执的记录必须保留。

### 3.3 复核确认人

1. 使用本人的企业个人账号登录，核对页面展示的姓名、岗位和账号编号。
2. 打开待确认草稿，确认矿井、统计窗口、当前修订号和来源材料与待复核任务一致。
3. 逐条对照业务系统、原始台账和审批材料，使用页面的核对按钮保存每一条观测的本人
   核对记录。
4. 确认核对进度为“全部已核对”。其他账号以前留下的核对记录不能替代当前确认人本人
   的核对。
5. 重新运行预检，确认没有阻断问题。预检通过只表示自动规则未发现阻断，不证明事实
   真实，也不代表监管认可。
6. 如同时承担治理职责，进入任务中心治理页，核对提案来源、内容、允许工具和修订号。
   记忆需要 `governance_review`，技能需要 `skill_admin`；共享记忆与所有技能的
   批准必须由提案人之外的另一名治理人员完成。`confirm` 本身不授予治理能力。
7. 阅读真实性声明，主动勾选接受，再点击“完成人工确认”。治理提案审批不能替代
   这一步，企业确认也不会自动批准治理提案。
8. 确认页面显示确认人、岗位、时间和当前版本已确认，再通知报送人员。

确认记录绑定当前草稿修订号、内容摘要和本人逐项核对证据。确认后只要业务内容发生
修改，旧确认就会失效；发生变化的观测核对也会被撤销，必须重新核对、预检和确认。
内置页面的确认方式只是“登录账号点击确认”，不冒充合格电子签名或企业章。

### 3.4 报送人员

1. 打开草稿第 6 步，先检查提交门禁：
   - 当前版本已有有效人工确认；
   - 当前账号拥有 `submit`，且不是待换密账号；
   - 监管平台已配置、可达并且合同兼容；
   - 当前没有同版本提交正在处理中；
   - 草稿尚未成功提交。
2. 查看确认人、确认时间、统计窗口、报送摘要和平台状态。
3. 点击提交并等待明确结果。提交处理中不要刷新后换新幂等键反复提交。
4. 若页面等待超时或状态不明，先刷新“提交记录”核对服务端状态，不要盲目再次报送。
5. 成功后保存回执号、接收时间和报送摘要。

网络类可重试故障应继续使用原幂等键；内容、权限、配置或治理类错误必须先修正原因。
平台“已接收”只表示技术接收成功，不代表数据正常、合法、合规或审核通过。
`submit` 本身不授予 V2 计划、提案或治理审批能力；报送账号是否能做这些动作仍分别
取决于 `write`、`governance_review` 和 `skill_admin`。

### 3.5 全流程账号

全流程账号可依次完成“基本信息 → 导入来源 → 提取核对 → 提交前预检 → 账号确认
→ 提交回执”六步。但系统拥有全权限不等于组织制度允许一人包办。生产环境仍应按
本单位内控要求实施填报、复核、提交分离，并使用各自实名账号留痕。

## 4. 完整填报流程与交接点

| 阶段 | 主要动作 | 网页端最低权限 | 完成标志 | 建议交接信息 |
| --- | --- | --- | --- | --- |
| 1. 建立草稿 | 新建并填写企业、矿井、窗口、工况 | `read, write` | 草稿已保存并取得修订号 | 草稿编号、修订号 |
| 2. 导入来源 | 导入 JSON/CSV/文字或事件快照 | `read, write` | 来源、观测和字段溯源可查看 | 来源名称、缺失凭证 |
| 3. 整理数据 | 采纳建议、手工修正、回答缺项 | `read, write` | 待报内容完整 | 修改说明、异常依据 |
| 4. 预检 | 运行完整性和逻辑检查 | `read` | 阻断项为 0 | 预检时间、需说明项 |
| 5. 逐项核对 | 当前确认人逐条核对全部观测 | `read, confirm` | 本人核对进度为全部 | 确认人、当前修订号 |
| 6. 人工确认 | 接受声明并确认当前版本 | `read, confirm` | 当前修订号显示已确认 | 确认时间、内容摘要 |
| 7. 监管提交 | 发送并获取回执 | `read, submit` | 状态为提交成功 | 回执号、接收时间、摘要 |

页面保存和确认请求携带当前 `expected_revision`。若出现“草稿已更新，当前修订号为
……”的提示，说明已有其他人或任务生成了新版本。不要覆盖对方修改，应刷新后核对
差异并重新执行受影响步骤。

尚未人工确认、没有提交处理中记录、没有运行中智能体任务且未绑定启用计划的草稿，
可由 `write` 账号在二次文字确认后移除。该操作是软删除，但普通页面不会继续展示。
已经确认、正在提交或已经成功提交的记录不能删除；成功报送内容也不能直接修改，
更正应新建更正报送并保留原记录。

## 5. AI 工具、智能任务和对话边界

### 5.1 智能提取

符合合同的 JSON、CSV 会经过确定性校验后自动写入草稿并记录字段级来源，不需要
模型。“让 Agent 自动填入草稿”或“重新智能提取”在处理自由文字时，可能把用户
本次主动选取或粘贴的内容和脱敏后的最小草稿摘要发送给管理员配置的模型。模型只
返回候选建议，不会自动把自由文字建议、历史估计或物理推断写成当前事实。点击采纳
属于人工编辑，需要 `write` 权限，并会形成新修订和审计记录。

仅运行一次模型提取也会保存模型辅助记录并生成草稿新修订，即使模型没有给出建议，
或用户尚未采纳建议，也可能使旧的企业确认失效。因此已确认版本不要随意重新运行
提取；确需运行时，应在完成后重新核对修订号和逐项复核状态，只对因观测变化而失效
的项目重新复核，再运行预检并确认当前版本。

未配置模型或模型不可用时，JSON/CSV 导入、预检、确认和提交等确定性能力仍可使用；
系统不会猜测性补齐文字材料中的数据。

### 5.2 煤炭智能任务

系统当前提供 20 个只读确定性煤炭工具，覆盖草稿治理、来源血缘、时间连续性、单位与
物理复算、多来源与序列对比、库存、历史统计、煤质场景和综合解释。确定性只表示相同
输入可复算，不等于输入真实，也不等于监管认定。

- `read` 账号可以发起和查看本人的任务，也可以拒绝或取消任务；
- 只有任务创建时具有 `write` 的账号才可能让标准任务看到草稿补丁工具；
- 批准补丁时再次检查当前账号的 `write` 权限；
- 批准只对页面列出的单个工具动作、参数摘要和草稿修订号有效；
- AI 永远不能调用企业人工确认或监管提交；
- 任务和完整工具结果按创建账号隔离，其他账号不能直接查看。

“自动规划”可能使用已配置模型选择工具；“仅确定性工具”不调用第三方模型。一键
体检或绑定草稿的数据分析应优先查看标为“当前草稿/历史库绑定”的证据。标为“调用者
提供数值”的结果只是场景复算，不能证明企业数据库中确实存在该数据。

### 5.3 Agent V2、计划与治理

V2 的 `daily_coal_health` 不调用模型、外网、浏览器或草稿补丁。它对当前草稿形成
一个有界证据快照，四专家并行运行后由确定性反方核验器生成负责人摘要。任务、
步骤、尝试和状态事件均持久化；服务重启可恢复未结束的只读任务。

V2 任务只允许以下业务动作：

- `read`：手工发起、查看、取消、重试本人的只读任务；
- `write`：管理本人每日/间隔/事件计划，立即运行计划，提出记忆和技能；
- `governance_review`：审批记忆提案、撤销有效记忆；
- `skill_admin`：审批技能提案、停用有效技能目录版本。

治理“学习”不是自动训练。记忆提案要求明确作用域、值、理由和来源；共享记忆由另一
名记忆治理人员批准。技能提案只能引用本地只读、不联网工具，所有技能都由另一名
技能治理人员
批准。技能批准后只进入目录，`runtime_activation=approved_inactive`，不会在当前
服务热加载。把批准目录变成可执行能力仍需代码审查、测试、发布和显式注册。

计划只检查创建时绑定的既有草稿，不会自动抓企业系统、建立下一期草稿或改变统计
窗口。矿端 `edge-agent` 独立把只读遥测送给监管平台，不向企业 Agent 自动灌数。
完整状态、调度 API 和恢复说明见
[煤炭 Agent V2 耐久任务流与治理使用说明](煤炭Agent-V2任务流.md)。

### 5.4 煤炭业务对话

对话只接受煤炭生产、洗选、计量、煤质、运销、库存、能耗、安全和煤炭填报相关问题：

| 问题类型 | 处理方式 | 重要边界 |
| --- | --- | --- |
| 煤炭通识 | 本地知识或模型通识回答 | 不读取草稿，不作为企业事实或现场安全阈值认定 |
| 近期煤炭新闻 | 百度新闻优先、DeepSeek Web Search 后备，AI 基于搜索片段归纳 | 不抓取全文；来源和时间需人工打开核验 |
| 企业实际数据 | 绑定草稿后进入只读 Harness，以工具证据回答 | 不能修改草稿、确认、签名或提交 |
| 非煤炭、混合越界、提示注入或要求绕过审批 | 本地直接拒绝 | 不调用模型或工具 |

讨论“本矿、本月、当前草稿、这批数据”等实际情况时必须绑定正确草稿。新闻检索失败
时系统不会用模型记忆伪装成近期新闻；通识回答和新闻摘要也不能作为报送凭证。

### 5.5 禁止交给 AI 的内容

不得在导入材料、任务或对话中粘贴：

- 登录密码、Cookie、会话令牌或 CSRF 令牌；
- 模型 API Key、Bearer Token、运输 HMAC 密钥或来源签名密钥；
- 私钥、完整监管提交报文或无关个人敏感信息；
- 未经授权出境的商业秘密或与煤炭任务无关的内部材料。

导入文件、台账备注、搜索片段和工具结果都可能包含不可信文字。材料中出现“忽略
规则”“替我提交”等指令没有系统权限，用户也不应据此批准工具动作。

## 6. 前端分级操作说明展示规则

前端应按有效能力做加法展示，不能通过 `role`、姓名或账号名称猜测权限。推荐判断
顺序如下：

1. 未登录：只显示登录说明，隐藏业务操作指南。
2. `temporary_demo=true` 或 `must_change_password=true`：优先显示醒目的待换密
   提示；可以继续按现有 `read/write` 展示体验说明，但确认、提交和治理审批始终
   标为不可用。
3. 有 `read`：显示“您可以查看、预检、运行/取消/重试本人 V2 只读体检和煤炭
   对话”。
4. 有 `write`：追加“您可以新建、导入、编辑和移除未提交草稿，管理本人 V2
   计划，提出治理提案，并批准旧版任务草稿补丁”。
5. 有 `confirm` 且非待换密：追加“您可以逐项核对并确认当前版本”。
6. 有 `submit` 且非待换密：追加“您可以提交已有效确认的版本并保存回执”。
7. 有 `governance_review` 且非待换密：追加“您可以审批或撤销业务记忆”。
8. 有 `skill_admin` 且非待换密：追加“您可以审批或停用只读技能目录版本”。
9. 六项权限齐全且非待换密：可概括显示“可完成全流程”，同时保留 AI 和监管边界。
10. 没有 `read`：显示“账号权限组合不适合网页端，请联系管理员补充 read”，不要把
   其他权限渲染成可独立完成的流程。

推荐的页面说明文案：

| 条件 | 标题 | 简短说明 |
| --- | --- | --- |
| 仅 `read` | 当前为查看账号 | 可查看、运行 V2 只读体检并留存结果；不能管理计划、改变草稿或执行正式确认、提交。 |
| 含 `write` | 当前可填报和修改 | 可整理数据、管理计划、提出治理提案及批准单项草稿补丁；修改会使旧确认失效。 |
| 含 `confirm` | 当前可复核确认 | 业务确认必须由本人逐项核对全部观测并主动确认当前修订；不包含治理审批。 |
| 含 `submit` | 当前可执行报送 | 只能提交已经有效确认且通过全部门禁的版本。 |
| 含 `governance_review` | 当前可治理业务记忆 | 可审批、拒绝或撤销记忆；不能据此确认草稿或管理技能。 |
| 含 `skill_admin` | 当前可治理技能目录 | 可审批、拒绝或停用只读技能目录版本；不能据此确认草稿或管理记忆。 |
| 待换密或 demo | 当前为临时或待换密账号 | 可体验已授权功能，但不能留下正式核对、确认、提交或治理审批。 |

按钮禁用时应尽量显示具体原因，而不是只显示“无权限”：

- 新建、编辑、导入、删除不可用：缺少 `write` 或草稿已提交；若同版本正在提交，
  页面部分编辑控件当前可能仍可见，但后端会拒绝修改或删除，应先刷新提交记录；
- 正式逐项核对不可用：缺少 `confirm`，或账号待换密，或草稿已提交；
- 确认不可用：未由当前账号核对全部观测、必答追问未完成、存在预检阻断、缺少
  `confirm`、待换密、修订已变化或草稿正在提交/已提交；
- 提交不可用：缺少 `submit`、待换密、确认无效、平台未配置/不可达/不兼容、已有
  提交处理中或已经成功提交；
- 记忆审批/撤销不可用：缺少 `governance_review`、账号待换密、修订已变化，或
  不满足共享作用域四眼审批；
- 技能审批/停用不可用：缺少 `skill_admin`、账号待换密、修订已变化，或审批人与
  提案人相同；
- AI 补丁批准不可用：缺少 `write`，不是本人任务，批准记录已处理，或草稿修订、
  工具定义/参数摘要已经变化。

这些说明只能帮助用户理解页面，不能代替后端权限校验。所有修改、确认和提交接口仍
必须由服务端根据当前登录会话、CSRF、修订号和业务状态再次判断。

## 7. 常见问题

### 7.1 岗位显示“管理员”，为什么按钮仍不可用？

`role` 是展示和审计字段，不授予权限。请查看账号实际 `permissions`、是否
`must_change_password=true`，以及草稿和平台门禁状态。

### 7.2 使用 `demo / 123123123` 为什么不能确认？

demo 是本机临时账号，固定标记为待换密，只允许查看和编辑体验。正式确认和提交由
后端强制禁止，不能通过修改前端按钮绕过。

### 7.3 有 `write` 权限，为什么不能勾选正式核对？

逐观测正式核对属于 `confirm` 权限，不属于普通编辑。请把草稿交给确认人，或由
管理员按组织职责配置权限。

### 7.4 有 `confirm` 权限，为什么仍不能确认？

依次检查：是否待换密；是否由当前账号逐项核对了全部观测；必答追问是否全部完成；
预检是否还有阻断项；页面修订号是否过期；草稿是否正在提交或已经提交。其他账号的
核对记录不能替代本人核对。

### 7.5 确认完成后为什么又变成未确认？

任何有效业务修改都会生成新修订，并使旧确认失效。变化观测的旧核对记录也会自动
撤销。这是防止“确认旧内容、提交新内容”的安全机制。

### 7.6 预检全部通过，能否直接认为数据真实合规？

不能。预检和煤炭工具用于检查完整性、格式、物理关系和统计异常，不验证全部现场
事实。真实性由企业人员结合原始凭证确认，正常性和合法性仍由监管侧独立判断。

### 7.7 AI 能否自动确认或提交？

不能。模型、智能任务和煤炭对话都没有人工确认和监管提交工具。标准任务中的唯一
写能力是受控草稿补丁，而且必须由具有 `write` 权限的本人逐项批准。

### 7.8 为什么我看不到其他人的智能任务或对话？

任务和会话按登录账号隔离，这是当前的隐私与越权防护。需要共享结论时，应通过草稿
编号、回执和组织批准的工作渠道交接，不要共享账号。

### 7.9 为什么草稿不能删除？

删除需要 `write`、当前修订号和二次文字确认。已经人工确认、正在提交、已经成功
提交、有排队或运行中智能体任务、有未结束 Harness 运行或绑定启用计划时都会锁定。
先取消任务、停用计划或等待运行结束；只有普通 `draft` 状态可以软删除。

### 7.10 提交超时后能否再点一次？

先刷新提交记录。状态不明时不要生成新幂等键盲目重复提交；网络类故障应使用原
幂等键安全重试。若平台已经返回成功回执，系统会恢复该记录。

### 7.11 模型 API 配置成功，为什么新闻仍可能失败？

通用模型、百度新闻和 DeepSeek Web Search 是不同运行通道。模型可用不代表搜索
提供商一定可达。应查看页面显示的实际检索渠道、时间、回退状态和失败原因。

### 7.12 修改账号、模型或监管平台配置后为什么没有立即生效？

这些配置由启动环境或密钥系统注入，服务不会在网页中临时保存 API Key。管理员更新
环境配置后需要重启服务；普通用户不应在对话、草稿或浏览器中填写这些密钥。

### 7.13 为什么 V2 任务在我关闭页面后还在运行？

V2 是服务端耐久任务，任务先写入 SQLite，再由后台工作线程执行。关闭页面只停止
浏览器显示，不等于取消。需要停止时应在任务详情点击“取消”；服务重启后未结束的
只读任务也会恢复。

### 7.14 为什么技能已批准仍不能在任务里选择？

批准只发布受治理目录版本，返回
`runtime_activation=approved_inactive`。当前服务不会热加载提案生成的技能。只有
经过代码审查、测试、发布和显式注册的能力才可能进入运行时。

### 7.15 为什么定时任务没有自动检查新一期草稿？

计划固定绑定创建时选定的草稿，不会自动找最新草稿、改统计窗口或抓取企业系统。
上游应先按受控流程建立新草稿，再更新或新建计划。当前仓库没有通用自动抓数或机器
账号适配器。

## 8. 安全与管理要求

### 8.1 普通用户

- 使用本人账号，不共享密码，不替他人核对或确认；
- 离开共享电脑前主动退出登录；
- 确认前核对页面展示的本人姓名、岗位和账号编号；
- 只导入授权范围内的业务材料，先去除无关个人信息和秘密；
- 不把模型建议、可信度、工具结果或平台回执当成事实真实性证明；
- 发现修订冲突、审计完整性失败或提交状态不明时停止操作并联系管理员；
- 保存正式回执和必要的原始依据，按本单位制度归档。

浏览器会话使用服务端 `HttpOnly; SameSite=Strict` Cookie，页面只在内存中保存 CSRF
令牌。显式退出后，页面会清除草稿表单、来源材料、对话、智能任务、回执、搜索条件
和旧身份等内存及 DOM 内容。会话意外过期时，仅为同一账号重新登录临时保留尚未保存
的草稿；改用其他账号登录或原账号已失去 `read` 权限时会立即清除。用户不应尝试
复制 Cookie、令牌或通过非同源页面调用接口。

### 8.2 系统管理员

- 使用最小权限配置账号，正式环境优先采用职责分离；
- 每个自然人使用唯一 `actor_id`，姓名和岗位填写真实审计信息；
- 通过 `enterprise-agent hash-password` 生成 PBKDF2 摘要，不保存明文密码；
- 新建临时账号时设置 `must_change_password=true`，完成安全换密后更新摘要并改为
  `false`，随后重启服务；
- 不在生产环境启用 demo 或匿名本机调试模式；
- 用户、模型和平台凭据由服务管理器或密钥系统注入，不写入仓库和日志；
- 修改权限后安排用户重新登录，并验证前端提示和后端接口均符合预期；
- 定期备份数据库、验证审计链、演练恢复，并保护状态盘和备份访问权限；
- 监控 V2 `blocked/failed` 任务、计划 `last_error`、待审批提案和技能
  `runtime_activation`，不要把目录批准误当作运行时加载；
- 为共享记忆和技能提案至少保留两名不同自然人的实名账号，禁止共享账号完成四眼
  审批；
- 对已离职、调岗或不再需要的账号及时从配置中移除并重启服务。
