# 十量 V3 企业智能体分级账号操作手册

本手册对应当前四页前端。岗位名称只用于显示，真实权限由
`GET /api/v1/auth/me` 返回的 `permissions` 决定；服务器对每个接口再次校验，
不能靠隐藏按钮代替授权。

字段代码、固定单位和标准 CSV 表头以
[十量 V3 部署与运行](../../docs/十量V3部署与运行.md)为准；本手册只说明岗位操作。

## 1. 权限与账号级别

| 权限 | 可以做什么 | 不能据此做什么 |
| --- | --- | --- |
| `read` | 查看本矿收件、月报、政府风险、对话和留痕 | 不能修改或确认 |
| `write` | 人工导入、受控直采、保存月报复核稿、填写风险回复 | 不能形成企业正式确认 |
| `confirm` | 参与正式确认门禁 | 单独具备时仍不能发送 |
| `submit` | 参与向政府发送门禁、手工触发 outbox | 单独具备时仍不能确认 |

当前 V3 把“确认并可靠入队”视为一个受控动作，因此月报和风险回复都必须由同一当前
登录账号同时具有 `confirm + submit`。如单位要求经办、复核、报送严格三岗分离，
应在后续合同中增加独立审批状态机；不要通过共享账号模拟多人审批。

建议配置：

- **监督查看人员**：`read`；
- **填报经办人**：`read, write`；
- **企业确认报送负责人**：`read, confirm, submit`；
- **全流程管理员**：`read, write, confirm, submit`，只给确需兼岗的实名人员。

`must_change_password=true` 或 `temporary_demo=true` 时，确认和提交始终被锁定，
即使 permissions 误配也不会放行。默认演示账号 `demo / 123123123` 属于这种状态。

## 2. 页面怎样按权限工作

前端只展示四个业务页：

### 数据收件箱

- `read` 可看接收时间、文件名、人工/直采来源、状态和 SHA-256 摘要；
- `write` 可从“上传 CSV，自动生成填报草稿”入口下载标准模板并上传，也可导入 ET/XLS/XLSX/JSON/JSONL，或立即扫描配置好的固定目录；
- CSV 选择后先显示映射预览。系统按本矿已批准映射、本地规则和可选的受约束模型建议识别日期、日合计、零点班、八点班、四点班及十量字段；模型只接收表头和脱敏类型统计，不接收原始数值；
- 黄色或红色列必须由经办人选择规范字段或“明确忽略”，重复映射会被阻止；勾选“保存为下次映射参考”必须是人员主动操作，默认不保存；
- 未知列、非法数字、疑似公式和口径歧义只形成待核对提示，不执行、不猜值；
- 上传只生成待复核稿，不直接发给政府；
- 同一内容再次上传显示“已经接收”，不重复建稿；
- 未确认且不再需要的稿件可由 `write` 用户填写原因后放弃；默认列表隐藏，勾选
  “查看已放弃记录”即可追溯；
- 解析失败的目录文件在 Agent 状态目录隔离，来源原件仍保留。

人工导入和直采并列合法。页面不会显示“人工低信任”“设备高信任”，政府算法也不应
因采集方式改变数值权重或阈值。

### 规范化复核与报送

- `read` 可看月报、来源和政府接收回执；
- `write` 可逐日核对风量、电量、火工品量、入井人员量、产量、开采量、销售量、
  运输量、洗煤量和开票量；火工品量内分别核对雷管和炸药子项。前七个原子字段可展开
  零点、八点、四点班，商业四量以日合计为强制口径；
- `invoiced_quantity_t` 只填非负的正常/蓝字发票实物吨数。红票、退票、作废、折让和
  退货应回到企业凭证辅助明细另存并另算净额，不得在主字段填负数；
- 空白表示 `null/缺失`，不能用 0 代替，也不会由智能体估算；
- 保存使用修订号，其他操作已经修改时会要求刷新，避免静默覆盖；
- “放弃草稿”只改变状态并写入原因和审计链，原始导入与规范化内容不会删除；
- `confirm + submit` 且非待换密账号，才能勾选声明并进入可靠发送队列。

政府接收回执只表示消息已可靠接收、排队分析，不代表数据正确、企业合法或监管认可。
页面明确显示这条边界。
已确认、已进入发送队列或已送达的月报不能放弃；风险报告、回复和政府回执也不能从
前端删除。

### 风险解读与回复

- `read` 可拉取和查看只属于本矿、通过政府应用签名验证的风险报告；
- 报告按 finding 展示标题、严重程度、日期、指标、方法、观测值、参考区间和分数；
- 对话只解释当前报告，允许询问 L1 求解器、最小冲突集、本矿历史基线、变化点和匿名
  同类矿证据；股票、天气、新闻、编程和娱乐等越界问题直接拒绝；
- `write` 可为每个 finding 填写回复类型、原因分类、核实事实、证据索引、措施和可选
  更正报表消息 ID；
- 证据原件不在对话或表单上传，只发送企业本地保留的元数据和 SHA-256；
- `confirm + submit` 才能正式回复。

企业原因说明只会留痕，不能自动消除风险。如果原报表数值错误，应先产生符合 V3
修订链的更正月报，再在回复中引用更正消息；政府用同一算法重算后才能改变结论。

使用了风险对话时，正式回复会自动记录 `agent_assistance.used=true`、会话编号和
对话记录摘要，不把智能体辅助伪装成人工独立结论。

### 留痕与设置

所有 `read` 用户可看：

- 本实例固定矿井、经营主体和企业系统；
- 政府接口是否配置、最近已确认 opaque cursor；
- 人工导入和直采数据均进入同一复核与报送流程；
- append-only 操作链的完整性、链头和逐项事件。

这些设置来自启动环境，前端不能切换矿井、改 HMAC、改政府地址或推进 cursor。
完整性失败时应立即停止业务处理并保全数据库，不要直接 SQL 修改事件或 hash。

## 3. 标准交接流程

### 经办人

1. 优先下载标准 CSV 模板并保持表头不变，填写本月每日数据。模板是日期加 11 个
   原子字段的 12 列日汇总；已有系统导出文件也可直接选择；
2. 点击“让 Agent 读取并预览映射”，逐列核对原表列与规范字段；黄色/红色项必须人工选择或明确忽略；
3. 点击“我已确认映射，生成草稿”，确认页面提示“当前尚未报送”；
4. 检查接收状态、是否重复以及未映射/非法单元格提示；
5. 进入月报复核，核对日期、运行状态、日报合计及三个班次；
6. 对缺失项回查原始日报；确实无法取得时保留 null 和缺失事实，不猜值；
7. 保存后把月报月份、草稿编号和待核对事项交给负责人。

### 确认报送负责人

1. 使用自己的实名账号登录，不使用经办人 Cookie 或共享密码；
2. 复核矿井、月份、期间、缺失数量、来源数量和重要日期；
3. 展开抽查日报及三个班次，核对单位和原件；
4. 填写姓名、岗位和本次确认说明，勾选声明；
5. 点击“确认并进入发送队列”；
6. 等待政府接收回执。网络失败时消息会按原 ID 重试，不要重复建稿。

### 风险办理人员

1. 在风险页拉取新报告，确认签发时间和回复期限；
2. 阅读每个 finding 的算法证据；
3. 可用对话理解核对范围，但不能让智能体替企业编造原因；
4. 对照日报、班次、检修、供电、通风、爆破和生产计划记录；
5. 逐 finding 填事实、证据索引和措施；
6. 由有权负责人确认发送；
7. 收到回复回执后继续等待政府记录/重算结果，不能把回执当作风险关闭。

## 4. 常见提示

| 页面提示 | 含义与处理 |
| --- | --- |
| “请登录” | 使用企业逐用户账号；本机演示可用 demo/123123123 |
| “临时/演示账号必须换密” | 当前账号只能体验查看和编辑，管理员配置正式密码摘要 |
| “缺少确认或提交权限” | 当前人员不能完成最终动作，按内部流程转交有权人员 |
| “同一内容已经接收” | SHA-256 防重正常生效；回到已有草稿，不改名绕过 |
| “草稿已被其他操作修改” | 刷新后重新核对，不覆盖另一人的修订 |
| “草稿已放弃” | 原文仍在本地；收件箱勾选“查看已放弃记录”可审计追溯 |
| “已确认、已入发送队列或已送达的草稿不能放弃” | 状态已经越过可撤回边界；保留记录并按更正/风险回复流程处理 |
| “已确认，待发送” | 消息已经持久入队；可等待后台或由 submit 人员触发一次重试 |
| “政府已接收” | 只是 intake receipt，继续等待分析报告 |
| “目前没有新报告” | next 接口返回空，不表示历史风险消失 |
| “报告签名失败” | 系统拒绝入箱；联系管理员核对政府 key、身份和时钟 |
| “回复已记录，风险未自动消除” | 正常设计；等待政府状态或更正重算 |
| “留痕完整性失败” | 停止使用结论、保全状态目录并进入安全事件处置 |

## 5. 密码与会话安全

- 正式密码从 `enterprise-agent hash-password` 产生摘要后配置；
- 不把明文密码、Cookie、CSRF、HMAC 或企业原始数据发到聊天、工单或截图；
- 浏览器 Cookie 为 HttpOnly，CSRF token 只存在页面内存；
- 离岗关闭浏览器或点击退出；
- 不多人共享同一账号，否则人工确认无法准确归责；
- 远程生产只经 HTTPS 反向代理访问，不能直接暴露 8090 明文端口。

## 6. 固定单矿边界

一个煤矿一个 Agent。即使同一集团代管多个矿，也不能在页面中切换矿井或让一个
智能体代表不同经营主体。每矿独立：

- `ENTERPRISE_MINE_ID` 和 `ENTERPRISE_OPERATOR_ID`；
- `ENTERPRISE_SYSTEM_ID / PLATFORM_V3_SENDER_ID`；
- 企业用户、数据库和隔离目录；
- 应用消息 HMAC、运输 HMAC 和 key ID；
- 固定目录 allowlist 和证据原件；
- outbox/inbox/cursor 和审计链。

政府 Platform 可以在监管侧做单矿或跨矿匿名统计与综合算法，但企业 Agent 只能看到
本矿收到的报告，不读取其他煤矿明细。

## 7. Legacy

旧版六步通用草稿、任意煤炭任务、新闻搜索、通用 Harness 和记忆/技能治理仍可能在
代码中用于历史迁移，但已从默认页面隐藏，不属于本手册流程。不得依照旧说明启动
`edge-agent` 第三产品或用 V1、五量 V2 接口替代十量 V3。五量 V2 只允许历史只读
复核，不能补造新增字段后重新确认。
