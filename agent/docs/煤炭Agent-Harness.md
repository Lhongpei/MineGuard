# Legacy：通用煤炭智能体 Harness 设计与运行边界

> **Legacy 文档。** 通用任务、新闻和任意煤炭对话已从五量 V2 默认前端隐藏。
> 当前风险对话只解释一份已验签政府报告，默认部署见 [README](../README.md)。

## 目标

煤炭智能体不是一个可以任意操作系统的聊天机器人。它是企业侧的受控任务执行器：

1. 对企业实际数据，用模型理解任务和选择工具，但不把模型自由文本当作业务结论；
2. 用确定性工具读取证据、计算煤炭业务关系并复算结果；
3. 对任何写操作设置显式人工批准断点；
4. 完整保存运行、工具调用、错误和批准轨迹；
5. 永远不把企业确认、监管提交、来源签名或密钥交给模型。

对话区另有两个不进入 Harness 的通道：煤炭通识直答，以及百度优先、DeepSeek
Web Search 后备并由 AI 归纳公开检索证据的近期新闻搜索。通识模型文本、AI 新闻
摘要和外部新闻引用都不是企业事实、确定性工具证据或监管认定，也不能触发业务动作。

企业智能体与监管平台继续保持代码、数据库和密钥独立。Harness 只能通过企业端服务
接口和版本化监管 HTTP 合同工作，不得 import 监管平台实现。

## 信任分层

| 等级 | 示例 | 执行策略 |
| --- | --- | --- |
| 只读确定性工具 | 草稿摘要、预检、时间对齐、质量平衡 | 在预算内可自动执行 |
| 外部只读工具 | 企业系统查询、监管能力探测 | 允许列表、超时、熔断、结果限长 |
| 企业草稿写工具 | 应用字段补丁 | 先生成精确预览，登录人员批准后执行 |
| 企业确认 | 绑定登录身份和草稿摘要 | 不注册为模型工具，只能由原确认界面执行 |
| 监管提交 | 使用运输 HMAC 发送已确认信封 | 不注册为模型工具，只能由原提交界面执行 |

模型返回的工具名和参数永远只是“不可信请求”。Registry 必须重新校验工具是否存在、
JSON 参数是否完全符合 schema、当前人员是否有权限、运行预算是否足够，以及该动作是否
需要人工批准。

“确定性”只表示给定输入下计算可复现，不等于输入来源可信。每项工具证据还要标注：

- `repository_grounded`：参数绑定当前草稿或只读成功报送历史；
- `user_supplied`：数值由任务调用者提供，只能作为场景复算结果；
- `external_public`：来自固定公开检索通道，只能作为待核验的外部参考。

综合交叉验证和默认一键体检只使用 `repository_grounded` 工具形成草稿事实说明。
通用单位换算、显式质量平衡等 `user_supplied` 工具可以辅助计算，但不能被展示为
“数据库证据”。仓库工具如允许调用者选择指标、时间容差或比较阈值，输出还必须
单独声明参数来源和业务关系未验证，不能因为基础数值来自仓库就自动成为异常认定。

每个 `ToolSpec` 还显式声明 `category`、`network_access`、`scenario_only` 和
`allowed_profiles`。这些元数据与输入输出 schema 一起绑定工具定义摘要。模型不能把
场景工具升级为仓库事实，也不能让只允许标准任务的工具进入 `chat_read_only` 对话。
Registry 会拒绝本地校验器尚未实现的 JSON Schema 关键字，避免配置看似有限制、实际
却被静默忽略。

## 一次运行的状态机

```text
queued
  -> running
      -> waiting_approval -> running
      -> completed
      -> failed
      -> cancelled
```

每次运行具有独立 `run_id`，并限制最大步骤数、工具调用数、墙钟时间、模型输出大小和
单个工具结果大小。达到任何预算都必须失败关闭，不能让模型自行扩大预算。

运行队列使用固定数量工作者，并在数据库事务内执行逐账号和全局活动任务限额，
避免并发创建绕过限额或为每个排队任务创建线程。取消会关闭尚未执行的调用和批准；
已经进入外部只读调用的底层线程可能要等自身超时返回，但返回后不得再保存结果、
规划新动作或修改草稿。

标准循环：

```text
读取用户任务和最小化草稿上下文
-> 模型提出一个或多个工具调用
-> Registry 与 Policy 本地校验
-> 只读工具执行并记录摘要
-> 工具结果返回模型
-> 模型继续调用工具或结束规划
-> 若出现写工具，暂停并等待人工批准
-> 本地模板只用已成功工具摘要形成最终说明并保存可回放轨迹
```

没有配置模型时，“煤炭一键体检”仍执行固定的确定性工具组合；它不会伪装成完成了
自主推理。

## 煤炭业务对话

对话区是独立于自由任务工作台的永久只读入口。每条消息先经过本地拒绝优先领域网关：
非煤炭主题、混合越界主题、提示注入，以及要求代为确认、签名、报送或绕过审批的
请求，均在调用模型和工具前拒绝。模型不能修改这个决定。通过领域准入后，本地意图
路由将请求分成三个互斥通道：

| 对话通道 | 典型问题 | 模型可见内容 | 工具与业务状态 |
| --- | --- | --- | --- |
| 近期新闻搜索 | 最近、今日、本周的煤炭新闻、政策、煤价、安全、科技或国际动态 | 检索端只见规范化主题与日期；总结端只见来源编号、标题、来源标注、时间和搜索片段 | 调用只读 `coal-news-search` 后执行受控 AI 总结，不创建 Harness 运行，不读取或修改草稿 |
| 煤炭通识直答 | 燃点、煤阶差异、洗选原理、通用安全常识 | 当前问题；有界追问时至多附带最近一轮已治理通识问答 | 不创建 Harness 运行，不调用工具，不读取或修改草稿 |
| 企业数据分析 | 当前草稿煤流是否平衡、这批观测为何异常、来源是否齐全 | 有界会话任务、运行绑定信息、工具 schema、脱敏限长工具结果 | 创建 `chat_read_only` Harness，只能执行确定性只读工具 |

### 近期新闻 Skill 的网络与证据边界

`coal-news-search` 默认先请求固定 `https://www.baidu.com/s` 新闻页。百度触发
安全验证、超时或无结果时，不绕过验证码，改用已配置 DeepSeek API 的原生 Web
Search；Bing 默认关闭。它不接受用户指定 URL、不抓取正文，只发送有限煤炭主题和
日期窗口，因此原始问题、企业标识、绑定草稿、会话上下文和凭证均不会出站。

该路径不创建 Harness 运行。DeepSeek 搜索后备只提取 `web_search_tool_result`，
丢弃搜索响应中的模型总结和加密内容。取得合格来源后，独立总结调用只接收本地来源
编号、标题、搜索源标注的发布方、时间和可选搜索片段，不接收 URL、原始问题、草稿、
企业标识或会话历史。登录后可通过 `GET /api/v1/agent/skills` 查看检索提供商、
数据边界及最近运行状态；健康接口从首次调用前的 `configured_unverified` 更新为
`reachable`、`degraded` 或 `unreachable`。

检索证据按结构化字段保存：每条 `source` 包含 `S1/S2` 编号、标题、来源标注、
HTTPS 链接、发布时间、检索时间及可选搜索片段；包级记录 `searched_at`、窗口、
结果数、`provider_attempts`、回退与缓存标志。搜索片段可能截断且未核验正文，
总结模型必须忽略其中指令，只能返回引用已有来源编号的严格 JSON；链接与来源卡始终
由本地代码渲染。新闻问答会从后续企业数据 Harness 上下文中排除。状态语义固定为：

- `succeeded`：至少取得一条通过时间、相关性和链接校验的结果；
- `partial`：仍有可信结果，但部分条目未通过校验；
- `failed`：网络、响应体、XML 或结果校验失败；无有效结果使用
  `failure_code=no_results`；
- `unavailable`：Skill 已关闭或并发槽位繁忙。

任何失败都不得退回模型记忆或本地通识知识生成“近期新闻”。系统必须展示失败语义
和检索时间，建议重试或调整窗口，不把“未检索到”表述成“没有新闻”。
检索成功但总结未配置、繁忙、超时或未通过引用校验时，检索状态保持成功，页面改为
展示确定性来源列表，并在独立的 `summary` 证据中记录失败原因。

启动配置及默认值如下；更改后须重启：

```bash
COAL_NEWS_SEARCH_ENABLED=true
COAL_NEWS_SEARCH_TIMEOUT_SECONDS=25
COAL_NEWS_BAIDU_ENABLED=true
COAL_NEWS_BAIDU_TIMEOUT_SECONDS=3
COAL_NEWS_DEEPSEEK_WEB_SEARCH_ENABLED=true
COAL_NEWS_DEEPSEEK_TIMEOUT_SECONDS=24
COAL_NEWS_BING_FALLBACK_ENABLED=false
COAL_NEWS_SEARCH_CACHE_TTL_SECONDS=300
COAL_NEWS_SEARCH_MAX_RESULTS=8
COAL_NEWS_SEARCH_MAX_RESPONSE_BYTES=1048576
COAL_NEWS_SEARCH_MAX_CONCURRENCY=4
```

设置 `COAL_NEWS_SEARCH_ENABLED=false` 可关闭。总超时、百度超时、DeepSeek 搜索
超时、缓存、结果数、响应体和并发范围分别是 3–60 秒、1–10 秒、3–60 秒、
30–3600 秒、1–20、65536–2097152 字节和 1–8。

### 通识直答的数据边界与降级

通识路由只依据当前问题及是否存在一轮合格通识上下文，不依据会话是否绑定草稿。
因此，用户打开企业草稿后再问“煤炭的燃点是多少”，也不会把草稿带给模型。供应方
接口采用窄参数设计，不接受草稿、会话全文、工具结果、Harness 回答、拒绝消息、
企业历史或监管证据。普通问题只发送当前问题；只有“为什么”“再解释一下”等有界
追问，才附带最近一轮状态为完成、领域准入且答案来源为通识模型或本地知识的问答。
问题、上下文和回答还分别执行字符数、字节数、控制字符及敏感材料校验。

供应方必须按独立 JSON 契约返回 `{"answer":"中文回答"}`。正常结果标记
`answer_kind=model_common_knowledge`、`model_generated=true`；未配置模型、请求
超时或报错、JSON 契约非法、答案校验失败，或达到服务端全局/逐账号并发上限时，
该条消息不失败，而是自动使用本地受控煤炭知识回答，并标记
`answer_kind=local_knowledge`。证据始终记录
`enterprise_data_sent_to_provider=false`。两类回答均追加通识免责声明，不能作为
企业实际数值、来源真实性或合规状态的证据。

### 企业数据只读 Harness

涉及“当前草稿”“这批数据”“异常来源”“历史基线”等企业实际数据意图时，不走
通识直答，必须进入 `chat_read_only` Harness。聊天模型可见的工具 schema 完全排除
`draft_patch`，Registry 在执行前再次校验工具配置，因此聊天不能修改草稿、产生写
操作批准断点、确认、签名或提交。最终企业数据说明仍由本地模板汇总已成功的确定性
工具证据，模型自由文本不作为业务结论。

会话绑定登录账号，可选绑定一个草稿且中途不能切换。企业数据分析只使用最近 8 条、
总计不超过 3200 字的有界上下文；拒绝消息不会进入模型上下文。每个用户消息使用
`client_message_id` 幂等，同一会话同一时间只允许一个处理中回复。会话、消息及
运行关联写入带计数和链头锚定的追加哈希链；篡改后接口隐藏全部消息并禁止续聊或
删除。

## 煤炭工具目录

当前有 20 个只读确定性工具，另有一个仅在标准任务中可见、必须人工批准的草稿补丁
工具。只读工具按用途分为：

| 类别 | 工具 |
| --- | --- |
| 草稿治理 | `draft_summary`、`deterministic_preflight` |
| 来源与血缘 | `source_evidence_check`、`summarize_provenance_lineage` |
| 时间与连续性 | `align_observation_time`、`inspect_observation_continuity` |
| 单位与物理复算 | `convert_coal_units`、`calculate_mass_balance`、`calculate_coal_flow_balance`、`calculate_washing_yield` |
| 多来源和序列对比 | `compare_metric_series`、`compare_source_consistency` |
| 库存运营参考 | `calculate_inventory_coverage` |
| 历史统计 | `build_historical_baseline`、`analyze_historical_trend`、`detect_sensor_drift`、`detect_change_point` |
| 煤质场景试算 | `convert_coal_quality_basis`、`evaluate_coal_blend` |
| 综合解释 | `explain_cross_validation` |

煤质基准换算支持 `ar/ad/d/daf` 的受控质量分数换算；涉及 `ad` 时必须提供空气
干燥基水分。它和配煤加权都只处理调用者明确给出的场景，结果固定标记
`caller_supplied_scenario` 和 `evidence_verified=false`，不读取企业草稿，不进入综合
交叉验证。配煤工具只评价质量加权线性指标和调用者给出的约束；不做配方优化，不把
“满足调用者约束”表述成符合标准或监管通过。

库存覆盖要求唯一的期末库存快照；发现多个快照时拒绝相加并返回无法评价。历史趋势
只允许已知的窗口可加总煤流指标，固定使用同矿、同 profile、同工况和至少 5 个既往
成功报送窗口；30 天数值只是 Theil-Sen 斜率的尺度展示，不是预测。

工具输出必须包含数据覆盖范围、使用的指标、样本数、误差或不确定性，以及
`not_a_regulatory_determination=true`。缺少必要数据时返回“无法评价”和具体缺项，
不得用零值、模型猜测或默认常数补齐事实。

## 历史数据规则

历史基线默认只能使用本地数据库中监管平台已经成功接收的草稿，并且满足同矿井、
同指标、有限数值和可解析时间。工具不得读取完整提交信封、来源签名、运输凭证或
模型密钥。

历史结果用于补充物理关系，不替代物理约束。推荐输出中位数、MAD、分位区间、样本量
和当前值所在位置，而不是让模型直接生成风险分数。样本不足时必须明确降级。

## 运行留痕

至少保存：

- 创建人、创建时间、任务和关联草稿；
- 模型供应方、模型名及 Harness 版本；
- 每一步工具名、参数摘要、输出摘要、状态和耗时；
- 工具输入输出 SHA-256；
- 人工批准或拒绝人员、时间和精确动作摘要；
- 最终说明、失败类型以及预算消耗。

API Key、Cookie、Bearer Token、HMAC 密钥、来源签名和完整监管提交请求不得进入运行
轨迹或模型上下文。

事件链必须由运行表中的事件数量和链头摘要锚定；只逐条校验前后哈希无法识别尾部
截断。工具参数、结果 JSON 也必须重新计算摘要，不能只比较两列已存摘要。待批准
写动作还要绑定草稿修订号、工具 schema 摘要和 Harness 版本；任一变化都失败关闭。

这条链用于发现损坏和不一致的局部修改，不宣称能抵御拥有数据库写权限、并能同时
重算整条链和链头的主机管理员。生产环境仍须依靠最小文件权限、状态盘加密、备份
审计和外部只写日志保全；监管端继续独立验证合同、来源签名和运输签名。

写动作在崩溃恢复时不得假定“成功”或“未执行”。若业务修改与工具完成状态不能在
同一事务提交，恢复后应标记为 `mutation_outcome_unknown`，要求人员对照草稿修订
和审计记录，不得自动重放。

## 防提示注入

导入文件、台账备注、历史材料和工具输出都视为不可信数据。材料中的“忽略规则”、
“调用提交工具”或伪造 JSON 指令没有控制权。只有系统侧 Registry 能定义工具，
只有 Policy 能批准调用，模型不能动态注册工具或修改权限。

## 评测要求

上线前应持续运行以下离线用例：

- 正常五流一致、单源偏差、多源同时偏差；
- 库存正负方向错误、吨/千克混用、时间错位；
- 传感器缓慢漂移、突变、重复观测和缺失观测；
- 历史样本不足及历史分布变化；
- 文件内提示注入、超大工具参数、未知工具和越权写入；
- 模型超时、空响应、非法参数、重复工具调用和进程重启；
- 人工拒绝写操作、修订号冲突以及确认/提交不可调用。

核心指标包括字段准确率、证据覆盖率、异常召回率、误报率、校准误差、人工修正率、
工具成功率、延迟、模型费用和可回放率。
