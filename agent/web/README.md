# 企业可信数据填报前端

这是企业侧智能填报助手的纯静态中文前端。它与监管平台代码完全独立，仅通过企业侧后端的相对 HTTP API 通信，不读取或复用 `platform/` 下的代码、样式和资源。

## 按账号权限显示操作说明

登录后，工作区顶部会显示“当前账号操作说明”，包括岗位、四项权限状态、建议操作
顺序、当前可以做的事情，以及需要转交给其他人员的环节。说明只依据
`/api/v1/auth/me` 返回的 `permissions`、`must_change_password` 和
`temporary_demo` 生成；`role` 只是岗位展示文本，不能授予权限。

页面支持监督查看、填报经办、复核确认、报送执行、确认兼报送、经办兼确认、经办兼
报送、全流程和自定义权限组合。演示账号或待换密账号即使配置了 `confirm`、
`submit`，也会将这两项显示为“暂锁定”，并提示联系管理员处理。缺少 `read` 的异常
组合会安全降级，不会被描述成能够独立完成业务流程。

面向最终用户的岗位步骤、交接信息、按钮禁用原因和常见问题见
[分级账号操作手册](../docs/分级账号操作手册.md)。

## 使用流程

界面面向不熟悉算法的企业经办人，固定为六步：

1. 填写企业、统计时段，以及生产工况、班次、季节、检修状态四轴；
2. 导入 JSON、CSV 或粘贴业务文字，并声明材料来源；
3. 查看智能提取结果、每个数字的来源位置和提取可信度，逐项人工确认并回答缺项；
4. 运行完整性和逻辑预检；
5. 由有 `confirm` 权限的当前登录人接受真实性声明并完成账号点击确认；
6. 提交可信报送包，展示并留存监管平台回执。

智能提取在界面中始终标记为“待核对建议”，可信度只代表提取把握，不能作为真实性证明。任一数字未经人工确认、预检存在阻断项或签名无效时，提交按钮都不可用。

未提交草稿可以保存、撤销最近修改或经二次文字确认后删除；取得平台回执的报送会锁定，不能从企业侧直接删除。

页面另有独立的“煤炭智能任务”工作台。领导或经办人可对当前草稿一键发起体检，
查看任务进度、模型规划、本地确定性工具证据、资源预算和过程链完整性。只读账号
可以发起只读体检、拒绝或取消任务；草稿补丁必须由有编辑权限的任务创建者逐项
批准。智能任务永远不能调用企业人工确认或监管提交。

除固定的“一键煤炭体检”外，工作台还提供“全面体检”“解释异常与凭证”“历史趋势”
和“来源核验”四个领导易懂的任务模板。模板内容可编辑，也可输入任意 1–4000 字任务。
“自动规划”在模型可用时由模型选择只读工具，未配置模型时自动退回固定确定性流程；
“仅确定性”不会调用第三方模型。所有入口共用同一创建防重、超时后任务列表对账和
状态轮询逻辑，创建状态未知时不会自动重发。

“煤炭业务对话”是另一个独立入口，面向希望连续追问的领导用户。它只接受煤炭生产、
洗选、计量、煤质、运销、库存、能耗、安全和煤炭填报相关问题；越界问题会显示明确
拒绝，不会包装成业务答案。新建对话时可以选择当前草稿作为只读背景，对话不能确认、
签名或报送。消息使用一次性 `client_message_id` 防重；后端异步处理时页面有限轮询，
等待状态不明时锁定发送按钮，避免重复提问。会话可以切换，也可以二次确认后移除。
“最近煤炭相关新闻”等时效性问题会调用独立的 `coal-news-search` 新闻检索 Skill；
Skill 使用百度新闻优先、DeepSeek 原生 Web Search 后备的检索链路；取得来源后，
DeepSeek 根据标题和搜索片段生成带来源编号的 AI 摘要。模型参数存在不等于每个
新闻源都可用，页面会分别展示实际检索渠道、总结状态和受控失败原因。

对话按问题性质提供两个通道。普通煤炭通识问题（例如煤的着火特性、煤质指标含义或
洗选产率概念）可以直接使用本地知识或模型通识回答，不要求先绑定草稿，也不会假装
读取了企业数据。涉及“本矿、本月、当前草稿、这批数据为什么异常”等企业实际情况时，
应绑定草稿并由只读工具计算；只有成功工具记录和对话完整性同时有效，页面才把它标为
企业数据分析。模型通识文字本身不是企业数据事实、来源凭证或监管结论。

每条助手回答上方都会显示来源徽标：

- **本地煤炭常识**：来自程序内置、可复核的煤炭知识，未核验企业实际数据。
- **模型通识解释**：由大模型生成的一般说明，可能需要专业人员复核，不能当作企业数据事实或监管结论。
- **AI 联网摘要**：搜索成功，且 AI 已根据标题和搜索片段生成通过引用校验的摘要；
  未读取新闻全文。
- **联网新闻检索**：搜索成功且至少返回一条通过安全校验的 HTTPS 新闻来源，但
  AI 摘要未配置或暂不可用。
- **部分检索**：只获得部分有效来源，页面明确提示结果可能不完整。
- **未检索到结果**：搜索已执行但没有获得通过校验的来源，不代表这段时间一定没有新闻。
- **检索失败**：搜索服务不可用、调用失败或没有合法来源；不会用模型记忆伪装成近期新闻。
- **草稿工具证据**：已对关联草稿成功执行只读工具；仍需结合原始凭证和现场情况人工复核。
- **只读工具计算**：工具完成了复算，但没有声明为草稿仓库绑定来源，不能据此证明输入真实。
- **范围控制**：问题超出煤炭业务边界，服务未将其作为业务分析处理。
- **回答来源未标注／工具记录未验真**：旧版或不完整响应未提供足够依据；页面会谨慎降级，
  不把它展示成企业数据证据。显式完整性失败时则直接隐藏全部消息正文。

## HTTP 接口

所有请求集中封装在 `app.js` 顶部的 `api()` 与 `endpoints`，根路径固定为 `/api/v1`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/auth/login` | 登录企业账号并建立 HttpOnly 会话 |
| `GET` | `/api/v1/auth/me` | 恢复当前 principal、权限和 CSRF 令牌 |
| `POST` | `/api/v1/auth/logout` | 注销服务端会话 |
| `GET/POST` | `/api/v1/drafts` | 草稿列表/新建 |
| `GET/PATCH/DELETE` | `/api/v1/drafts/{id}` | 草稿详情/保存/删除未提交草稿 |
| `POST` | `/api/v1/drafts/{id}/import` | 导入 JSON、CSV 或文字来源 |
| `POST` | `/api/v1/drafts/{id}/assist` | 智能提取并生成缺项追问 |
| `GET` | `/api/v1/drafts/{id}/questions` | 获取缺项追问 |
| `POST` | `/api/v1/drafts/{id}/validate` | 提交前预检 |
| `POST` | `/api/v1/drafts/{id}/confirm` | 人工声明与签名 |
| `POST` | `/api/v1/drafts/{id}/submit` | 提交监管接口并返回回执 |
| `GET` | `/api/v1/agent/tools` | 读取工具目录、风险与批准要求 |
| `GET/POST` | `/api/v1/agent/runs` | 分页读取本人任务/发起任务 |
| `GET` | `/api/v1/agent/runs/{id}` | 查看步骤、工具证据、预算与审计完整性 |
| `POST` | `/api/v1/agent/runs/{id}/cancel` | 取消尚未结束的本人任务 |
| `POST` | `/api/v1/agent/runs/{id}/approve` | 批准或拒绝绑定参数摘要的单个写动作 |
| `GET/POST` | `/api/v1/chat/sessions` | 读取本人对话/新建煤炭业务对话 |
| `GET/DELETE` | `/api/v1/chat/sessions/{id}` | 读取或移除本人对话 |
| `POST` | `/api/v1/chat/sessions/{id}/messages` | 发送带幂等编号的煤炭业务问题 |

发起任务的请求体为：

```json
{
  "task": "1 到 4000 字的任务要求",
  "draft_id": "当前草稿编号",
  "mode": "auto"
}
```

`mode` 只能是 `auto` 或 `deterministic`。浏览器不会向智能体传递模型密钥，
也不会因创建请求超时而自动再次发送。

新建对话传递 `title`、可选 `draft_id` 和一次性 `client_request_id`；发送消息传递
`content`、可选 `draft_id` 和一次性 `client_message_id`。消息接口可以同步返回结果，
也可以返回 HTTP 202、`run_id` 或状态为 `processing` 的助手消息，页面会每约 1.3 秒
读取会话，最长自动等待 90 秒。对话响应若显式携带 `integrity`，只有
`valid === true` 才展示消息；`false`、`null` 或畸形结构会立即清空正文、停止轮询，
并禁用该会话的发送和移除操作。完全缺失该字段时仅用于兼容旧服务。

新闻回答在消息 `evidence` 中声明 `answer_kind=news_retrieval`、
`skill_name=coal-news-search`、检索状态、独立总结状态和最多十项来源。来源卡显示
`S1/S2` 编号；百度的 `sourceName` 标为“百度标注来源”，`summary` 标为“搜索片段
（可能截断，未核验正文）”。页面只创建通过安全校验的 HTTPS 链接，拒绝带用户名或
密码的 URL、`javascript:`、`data:`、localhost、私网字面 IP 和 IPv6 字面地址。
所有标题、来源标注、片段和时间均作为纯文本渲染；外链固定使用
`noopener noreferrer` 和 `no-referrer`。没有合法来源时，即使后端声称
`status=succeeded`，页面也会降级显示“检索失败”。

具体字段兼容处理收敛在 `normalizeDraft()`、`toDraftPayload()` 和 `applyServerDraft()`，不要在视图事件里散落接口适配逻辑。

界面的友好分组会在接口层转换为独立合同的平铺字段：
`enterprise_id`、`enterprise_name`、`unified_social_credit_code`、
`mine_id`、`mine_name`、`window_start`、`window_end`、
`profile_id`、`profile_version`、`operational_context` 和 `observations`。
保存时携带 `expected_revision`，避免两名经办人无意间覆盖彼此修改。

浏览器不保存会话令牌：后端仅设置 `HttpOnly; SameSite=Strict` Cookie，
`csrf_token` 只保存在当前页面内存，所有修改请求自动发送
`X-CSRF-Token`。确认人 ID、姓名和岗位只读展示 `/auth/me` 返回的 principal，
确认请求只发送 `confirmation_method=authenticated_click`，不会让用户下拉选择
未经验证的“数字签名”或“企业章”。临时 demo/待换密账号可以体验查看和编辑，
但前后端都会禁止确认、提交。

JSON/CSV 先走确定性导入，文字材料交给可选模型产生逐条建议。模型建议不会自动写入草稿，
经办人点击“核对后采用”才通过 `PATCH` 形成一次人工编辑。未配置模型时，文字材料不会被
猜测性解析，界面会继续提供规则校验和缺项提示。特殊事件只上报已批准事件编码，编码必须
来自批准工单或文件；材料位置由字段来源记录保存。

浏览器端不包含模型 API Key。模型调用、原始文档安全处理、身份校验和监管平台凭据必须只存在于企业侧后端。

工具卡片区分“仓库事实绑定”“调用者提供数值”和“模型规划”。确定性只表示相同
输入会得到相同计算结果，并不自动证明输入来源真实；监管人员应优先查看绑定当前
草稿或成功历史记录的工具证据。

工作台中的“AI 可用工具目录”读取 `/api/v1/agent/tools`，按服务端声明的业务分类
展示中文名称、只读/修改风险、批准要求、来源绑定、情景限制、联网属性和可用范围。
中文名称只是界面别名，卡片会同时保留精确技术标识；后端新增未知工具时会进入安全
降级分组，不会因前端映射缺失而隐藏。

成功工具卡片会提供默认收起的“结构化结果”：最多展示少量关键字段，并单独列出
不确定性、适用边界和限量证据预览。数组、对象、长文本和证据组均有数量、深度与
字符上限，敏感键和值会脱敏，所有内容只按纯文本创建；情景计算会明确标注不是监管
认定。完整结果仍以后端审计记录为准，页面不会一次展开整份载荷。

煤炭任务里的模型只负责规划调用哪些工具。模型自由文本不会作为最终业务答案展示；
最终摘要由后端用已完成工具记录生成。绑定草稿但没有仓库绑定证据时，服务会改跑
固定确定性体检。

后端通过字符串字段 `evidence_grounding` 声明输入来源。前端兼容工具调用顶层、
步骤 `evidence` 和工具结果 `data` 三个位置：`repository_grounded` 显示为
“当前草稿/历史库绑定”，`user_supplied` 显示为“调用者提供数值，仅复算不证明来源”，
`mixed` 显示为混合来源。任何未知值或缺失字段都显示“来源绑定未声明”，绝不推断为
仓库事实。

任务详情对过程链完整性执行 fail-closed：响应完全没有 `integrity` 字段时兼容旧版本；
一旦响应带有该字段，只有对象中的 `valid === true` 才展示综合说明、工具步骤和审批详情。
`null`、畸形结构或其他值都会显示醒目的完整性失败提示、清除已有结果并禁用批准和拒绝。仍在运行的任务
保留“取消任务”作为安全停止手段，完整性失败不会阻断取消。

## 本地查看与检查

由企业侧后端将此目录作为静态资源提供。仅查看样式时也可在仓库根目录运行：

```bash
python -m http.server 8090 --directory agent/web
```

此时后端 API 不存在，页面会明确显示“企业填报服务未连接”，不会伪造成功数据。

静态检查：

```bash
node --check agent/web/app.js
python -m pytest agent/tests/test_frontend_static.py
```

前端只使用 `textContent`、`createElement` 和 `replaceChildren` 构造动态内容，禁止把服务端或模型文本当作 HTML 字符串注入。
