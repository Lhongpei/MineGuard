# 企业十量 V3 自动采集与自动填报部署指南

本文用于把 ERP、MES、地磅、能耗、通风、火工品和入井台账中的只读数据，自动形成
企业 Agent 的“十量 V3 待复核草稿”。自动化终点是草稿和数据就绪预检，不是企业
确认，更不是监管认定。

> **当前适配边界：** Agent 的 CSV/工作簿/JSON 导入和 `connector-service` 都已面向
> 十量 V3。连接器规范化器固定输出 11 个原子字段，并已通过真实 Agent HTTP 端到端
> 验证；仍只有六字段的旧来源会把新增五项显式保存为 `null + missing`，绝不使用 0、
> 历史均值或模型补齐。连接器只创建待复核草稿，不能确认、签名或向政府报送；正式
> 启用前仍须完成本矿映射、来源、缺失场景和影子运行验收。

## 1. 运行边界

```text
企业来源系统（只读账号/只读文件）
        │
        ▼
connector-service（字段映射、缺日显式化、持久重试）
        │  独立 HMAC 密钥
        ▼
单矿 enterprise-agent（多来源合并、冲突阻断、待复核草稿）
        │  具名企业人员确认后，使用另一组 V3 密钥
        ▼
政府 platform（独立验签和唯一监管算法）
```

- 一个 Agent 实例只代表一个煤矿和一个经营主体。
- 一个 Agent 只配置一个权威自动采集客户端；多个数据来源在该客户端内部按
  `source_id` 分开。这样同一统计月不会产生两份互相竞争的机器草稿。
- 连接器不能访问政府接口，不能调用确认/报送接口，也不能持有企业到政府的密钥。
- Agent 和 Platform 不 import 对方代码、不共享数据库；连接器也不 import 二者代码。
- 原始值不交给 LLM 决定。字段映射、单位换算、归约和合并均为可复现的确定性规则。

自动采集目标字段固定为：`ventilation_m3_min`、`electricity_kwh`、
`detonators_count`、`explosives_kg`、`mine_entry_persons`、`production_t`、
`extraction_t`、`sales_t`、`transport_t`、`wash_feed_t`、
`invoiced_quantity_t`。火工品两项不能相加；产量和开采量必须来自各自批准的业务口径；
运输量只取出矿/外运净吨数，洗煤量只取入洗原煤。

开票主字段只能归约正常/蓝字发票的非负实物吨数。连接器遇到红票、退票、作废、折让
或退货时，必须把它们保留为带原单引用和发生时间的辅助事件，不能用负数覆盖
`invoiced_quantity_t`；净开票量由辅助事件另算。字段单位、日报/班次要求和标准 CSV
见 [十量 V3 部署与运行](十量V3部署与运行.md)。

## 2. 部署前需要企业提供什么

每个来源至少需要以下材料，缺一项就先影子运行，不进入正式辅助流程：

1. 来源系统名称、责任部门和技术联系人；
2. 只读接口文档、只读数据库视图，或固定文件投递目录；
3. 一至三个脱敏样例，以及字段含义、单位、时区、日报/班次口径；
4. 11 个规范原子字段的映射和允许的归约方法；
5. 数据应到时间、允许延迟天数 `reporting_lag_days` 和停产时的真实表达方式；
6. HTTPS 主机、端口、私有 CA、网络 ACL；数据库只读账号由来源系统自身控制；
7. 每个来源固定的 `source_id`、`source_system` 和给经办人看的来源名称；
8. 本矿独立的连接器 HMAC 随机密钥、准确 NTP 时间和备份目录；
9. 谁负责处理缺失、映射错误、多来源冲突和 dead 队列；
10. 至少一个完整业务周期的影子运行验收记录。

禁止提供生产数据库写账号、任意 URL、全网通配 allowlist、个人账号密码、企业到政府
的报送密钥或模型 API 密钥。曾在聊天、工单、日志或代码中出现过的密钥必须先轮换。

## 3. 安装

连接器使用独立虚拟环境：

```bash
cd /home/sevan/coral/connector-service
python3 -m venv .venv
. .venv/bin/activate
python -m pip install .
enterprise-connector --version
```

Agent 和连接器使用同一把、仅用于自动建稿的随机密钥。该密钥必须与 Agent 到
Platform 的应用消息密钥、运输密钥都不同。

```bash
export ENTERPRISE_CONNECTOR_HMAC_SECRET='replace-with-random-at-least-32-bytes'
```

在 Agent 的受保护环境文件中登记权威客户端及允许来源。以最终发布包的
`agent/.env.example` 为准；真实值保持单行 JSON，不能写进浏览器或普通配置文件。
环境变量在进程启动时读取，修改后必须重启服务。

```bash
export ENTERPRISE_AGENT_CONNECTOR_CLIENTS_JSON='[{"client_id":"mine-qy-001-connector","secret":"replace-with-the-same-connector-key","permissions":["autofill"],"allowed_sources":{"blasting-file":{"source_system":"blasting-ledger","required":true,"freshness_max_seconds":3600},"production-http":{"source_system":"production-mes","required":true,"freshness_max_seconds":3600},"energy-sqlite":{"source_system":"energy-sqlite","required":true,"freshness_max_seconds":3600}}}]'
```

`allowed_sources` 是来源 ID 到受控策略的精确映射，不支持 `*`。`source_system`、
`required` 和 `freshness_max_seconds` 必须分别与连接器 TOML 的来源系统、
`required_sources` 和 `max_staleness_seconds` 完全一致。字符串简写只为旧的本机联调
兼容，正式环境必须使用上面的显式策略对象；来源改名或调整时效都按受控配置变更处理，
同时更新两端并重新影子运行。

## 4. 配置来源

复制 [完整 TOML 样例](../connector-service/examples/config.toml)，至少修改：

连接器接口版本 V1 每个配置必须且只能有一个 `[[pipelines]]`：它对应本矿唯一的十量
V3 月报流程；这里的 V1 是连接器到 Agent 的内部接口版本，不是政府交换合同版本。
ERP、MES、地磅、通风等异构系统都配置成这个 pipeline 下的多个 `sources`。若未来增加
其他报表类型，应发布带明确 report scope 的新合同，不能在本版复用全局来源策略。

- `service.agent_url`：本矿 Agent 根地址；
- `service.client_id`：与 Agent allowlist 完全一致；
- `service.secret_env`：只写环境变量名，不写密钥；
- `agent_allowed_hosts/ports`：精确白名单；
- `pipelines.enterprise_id`：必须等于本 Agent 的 `ENTERPRISE_OPERATOR_ID`；
- `report_type`：本版固定为 `five-quantity`；
- `required_sources`：判断一次完整来源代次何时到齐并发出 workflow trigger；Agent 对
  每次成功机器导入都执行绑定当前修订和摘要的只读体检，不能因未触发完整代次而漏检；
- `max_staleness_seconds`：该来源成功快照的最大年龄；V1 默认 3600 秒，生产应按真实
  应到频率显式配置，并与 Agent allowlist 完全相同；
- 每个来源的适配器、字段映射、时区、班次和延迟日。

三种适配器：

| 适配器 | 适用来源 | 关键防护 |
| --- | --- | --- |
| `file-drop` | ERP 导出 CSV/JSON、台账文件 | 固定目录、稳定窗口、拒绝符号链接、原件不删不改 |
| `http-poll` | MES/设备只读 API | 只发 GET、固定主机端口、DNS 固定、防 SSRF、拒绝重定向、大小/超时限制 |
| `sqlite-query` | 本机只读视图或导出库 | `mode=ro`、`query_only`、authorizer、deadline、只允许单条 SELECT/WITH |

HTTP 认证头只写成 `env:ERP_TOKEN`，实际 token 从进程环境读取。内网 HTTPS 使用
`agent_ca_bundle` 或来源级 `ca_bundle`，不得关闭证书校验。

连接器以企业时区计算“本地今日减 `reporting_lag_days`”作为应报截止日。截止日所在
月份从月初补到该日，更早月份补到月末；延迟跨过月界时，目标月份也随截止日切换，
不会把尚未到期的月末日期声明为已覆盖。来源完全漏掉的一天也会出现在草稿中，其
44 个“11 字段 × 日报/三班”原子数据格保持 `null + missing`，不会凭历史值或 0
填充。每个来源、
每个有记录月份至少要映射出一个非空规范值，核心字段还应设置 `required = true`；
否则按字段漂移/配置错误处理，不会形成“全空但成功”的快照。

快照的 `observed_at` 表示连接器本轮成功读取这一精确快照的时间，不是月报内最后一条
业务记录的日期；业务覆盖截止由 `coverage_as_of` 单独表达。历史月份因此可以在本次
重读成功后进入复核，但仍必须覆盖该月声明窗口并与当前已完成的快照摘要一致。

## 5. 首次运行

```bash
enterprise-connector validate --config /etc/enterprise-connector/config.toml
enterprise-connector run --config /etc/enterprise-connector/config.toml --once
enterprise-connector status --config /etc/enterprise-connector/config.toml
enterprise-connector check --config /etc/enterprise-connector/config.toml
```

`status` 总是输出 JSON；`check` 在 dead、必需来源为空/错误/陈旧或尚未就绪时返回非零，
可直接接监控。连接器会用独立、只读的 HMAC 健康消息报告成功不变、空结果、错误和文件
稳定等待；健康消息不带原始记录，也没有改草稿、删除、确认或报送权限。成功健康只有在
其快照摘要、自动建稿事件和来源修订都与 Agent 当前已完成贡献一致时才显示为新鲜。

验证通过后再作为常驻服务运行：

```bash
enterprise-connector run --config /etc/enterprise-connector/config.toml
```

常驻命令占用终端且暂无新输出表示正在等待下一轮，不是卡死。Linux 可使用
[systemd 样例](../connector-service/deploy/systemd/enterprise-connector.service)，容器可使用
[Dockerfile](../connector-service/deploy/docker/Dockerfile)。服务应与 Agent 同网段部署，
Agent 仍只监听回环或受控内网，并由 HTTPS 反向代理提供连接。

## 6. 企业人员怎样使用

登录企业端后进入“十量填报”：

1. “数据收件箱”显示自动连接器是否启用；
2. 打开待复核草稿，先看统计窗口。页面会明确区分“整月月报”和“月内统计窗口”；
3. 展开“自动填报依据”，核对认证客户端、来源系统、来源修订、导入时间和请求摘要；
4. 处理缺失整日报、缺失数据格、日报与三班不一致、多来源冲突或拒绝原因；
5. 对照来源系统逐日核对；不能因为自动预检为绿色就跳过原始凭证；
6. 只有具备 `confirm + submit` 的具名账号才能确认。机器客户端永远没有这两个权限；
7. 政府接收回执只表示已接收排队，不表示数据正常、合法或无风险。

草稿“删除”采用软放弃：保留原始导入、修订和审计事件，不做物理擦除。已确认、已排队
或已送达内容不能删除。机器草稿经人工编辑后自动同步会暂停，防止后台覆盖人工决定；
恢复时必须走页面的显式恢复流程并保留审计，不能让连接器静默覆盖。

## 7. 影子运行

影子运行是“真实抓取、真实建稿、真实预检，但不确认、不报送”。建议至少覆盖一个完整
结算周期和一次停产/检修场景。

每天记录：

- 来源应到/实到时间和最长延迟；
- 完全缺失日期、缺失数据格和未知运行状态；
- 单位换算及 `single/sum/average/latest` 是否符合业务口径；
- 日报与三班算术不一致；
- 多来源同一单元格冲突；
- 人工原报表与自动草稿的逐字段差异；
- connector pending/dead、重试次数和 Agent rejected 原因；
- 重启、断网、响应丢失、`A→B→A` 修订和备份恢复结果。

验收不是“运行无报错”，而是企业业务人员签字确认字段、单位、班次、截止日和来源定位
均正确。影子期所有草稿必须保持未确认状态；不要连接生产监管接收端做试验。

## 8. 故障与恢复

```bash
# 查看安全状态摘要，不显示凭据和原始记录
enterprise-connector status --config /etc/enterprise-connector/config.toml

# 仅重试未被 Agent 持久业务拒绝的传输型 dead 事件
enterprise-connector retry-dead --config /etc/enterprise-connector/config.toml

# 或精确指定一个事件
enterprise-connector retry-dead --config /etc/enterprise-connector/config.toml \
  --event-id cevt_xxx

# 人工修改暂停等 4xx 已持久拒绝：先在 Agent 恢复同步，再显式生成新修订
enterprise-connector supersede-dead \
  --config /etc/enterprise-connector/config.toml \
  --event-id cevt_xxx \
  --reason '具名复核人已在 Agent 恢复自动同步，确认重送相同来源快照' \
  --confirm SUPERSEDE-DEAD
```

普通 4xx/业务 409 不会无限重试；Agent 可能已永久记录该 `event_id` 的拒绝结果，不能
用 `retry-dead` 反复发送。先在“自动填报依据”处理原因，只有明确接受舍弃人工修改等
场景才使用 `supersede-dead` 生成新的来源修订和事件，并在 connector 恢复审计中留存
旧/新事件、原因和时间。
5xx、408、425、429 和明确的“事件处理中”才自动退避重试。

Agent 数据库与 connector 状态库共同决定幂等和来源修订。生产备份必须包含两者，记录
同一维护窗口和各自 SHA-256；恢复时优先成对恢复。Agent 单边回滚时可用
`enterprise-connector replay --config /etc/enterprise-connector/config.toml --latest --confirm REPLAY`
重放各来源最新已交付事件。connector 状态丢失
但 Agent 仍保留高修订时，从 Agent 证据页逐来源核对最新 revision，将该来源 TOML 的
`revision_seed` 临时/受控设置为此值；重建后的首事件使用 `seed + 1`。不得直接 UPDATE
SQLite 或清空幂等表。所有 seed 操作必须记录操作者、原因、Agent 证据和恢复后结果。

## 9. 生产硬要求

- Agent 和 connector 分别以无登录权限的专用系统账号运行；状态目录仅服务账号可读写；
- 跨主机只用 HTTPS，私有 CA 显式配置，NTP 偏差保持在签名窗口内；
- 反向代理对机器路径设置独立请求体上限、连接数、每客户端速率、读写超时和访问日志；
- Agent 端还会执行独立请求体限制、客户端来源白名单、时钟/nonce 防重放和耐久配额；
- 上游数据库账号仍须只读；连接器的 SQLite authorizer 不能替代来源权限；
- connector 状态库含待投递规范化数据，按业务数据等级备份和销毁；
- 日志只记录事件 ID、来源 ID、状态、摘要前缀和错误分类，不记录原始正文、token、HMAC；
- 每次映射或来源接口变更都重新影子运行；不能在线热改后直接沿用既有确认结论。

## 10. 上线检查

- [ ] 单矿、经营主体、时区、班制和 `client_id` 已双人核对；
- [ ] Agent 只登记一个权威 connector，且允许来源 ID/系统精确匹配；
- [ ] 三类密钥（连接器、V3 消息、V3 运输）互不相同并已进入密钥系统；
- [ ] URL、主机、端口、CA、目录和 SQL 只读权限已验证；
- [ ] 11 原子字段、单位、日报/三班、归约和延迟日已由业务部门签字；
- [ ] 缺日、冲突、人工编辑暂停和软放弃均已演练；
- [ ] 断网、服务重启、响应丢失、dead 重试和双库恢复均已演练；
- [ ] 影子运行差异闭环且未执行确认/报送；
- [ ] 企业具名账号、最小权限、备份、监控、告警和轮值人员已就绪。
