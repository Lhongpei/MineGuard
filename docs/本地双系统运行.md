# 本地双系统运行

本文用于在一台开发机上分别启动监管平台和企业填报智能体，并验证两者只通过
HTTP/JSON 契约交互。命令假定当前仓库路径为 `/path/to/coral`，需要 Python
3.11+、Bash 和 `curl`。

## 1. 边界和密钥对应关系

两套服务必须使用各自的虚拟环境、依赖和数据库：

```text
platform/.venv + platform/.mineguard/       监管侧
agent/.venv    + agent/data/*.db            企业侧
contracts/                                   中立规范
```

不得把 `platform/src` 加到智能体的 `PYTHONPATH`，也不得让监管平台 import
`agent/src`。`contracts/` 中只有协议文件、样例和独立校验脚本，不包含任一侧的
业务实现。

机器接入涉及两类不同的 HMAC：

| 用途 | 监管侧 | 企业侧 |
|---|---|---|
| 整个 HTTP 报文的运输认证 | `MINEGUARD_EXTERNAL_CLIENTS_JSON` 中某客户端的 `secrets` | 相同客户端的 `PLATFORM_CLIENT_ID` 和 `PLATFORM_TRANSPORT_HMAC_SECRET` |
| 每条设备/台账观测的来源签名 | 来源注册记录中的 `source_id` 与 `hmac_secret` | 设备/采集网关持签名密钥；智能体只接收预签名观测 |

运输密钥和来源密钥用途不同，不能复用。平台还会校验客户端绑定的
`enterprise_id` 和允许报送的 `mine_ids`；配置值必须与企业草稿一致。

文中 `DEMO_ONLY_...` 均为隔离本机演示值，不是生产密钥。生产环境应由
KMS/HSM 或服务管理器分别注入高熵密钥，不应使用 `.env`、命令
历史、聊天记录或代码仓库传递。任何曾暴露的真实密钥都应立即轮换。

## 2. 启动监管平台

在终端 A 安装监管端：

```bash
cd /path/to/coral/platform
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -c constraints.txt -e .
```

配置一个只允许企业 `ENT-001` 报送矿井 `M001` 的机器客户端并启动：

```bash
export MINEGUARD_ADMIN_PASSWORD='123123123'
export MINEGUARD_EXTERNAL_CLIENTS_JSON='[{"client_id":"enterprise-client-001","enterprise_id":"ENT-001","mine_ids":["M001"],"secrets":["DEMO_ONLY_change_transport_secret_32_chars"]}]'
mineguard serve \
  --host 127.0.0.1 \
  --port 8080 \
  --state-directory .mineguard
```

`secrets` 的第一项是当前运输密钥，轮换窗口可临时把上一把密钥放在后续项；完成
轮换后应删除旧值。每把密钥至少 32 字节。`mine_ids` 应列出最小授权范围，本地
演示也不建议使用通配符。

打开 <http://127.0.0.1:8080/>。当前演示约定账号为 `admin`、密码为
`123123123`。`MINEGUARD_ADMIN_PASSWORD` 只在空的 `auth.db` 首次创建管理员时
生效；若状态目录已有账号，它不会重置密码。此口令不能用于共享环境或生产环境。

检查无需登录的机器接入能力声明：

```bash
curl -fsS \
  http://127.0.0.1:8080/v1/enterprise-submission-capabilities
```

应能看到 `enterprise-submission-v1`、`hmac-sha256-v1` 和提交路径
`/v1/enterprise-submissions`。

## 3. 先登记分析配置和可信来源

运输 HMAC 只证明请求来自已配置的企业客户端，不能代替监管端来源治理。企业提交
之前，管理员必须在监管端独立审批和登记：

- 草稿引用的 `profile_id + profile_version`；
- 每个观测引用的 `source_id`、所属 `mine_id`、指标、单位、容差、有效期和
  来源 HMAC 密钥；
- 来源允许的计量语义、序列/修订和校准状态。

仓库提供 `M001` 的五量演示配置：

```text
platform/examples/governance/profile-five-flow.json
platform/examples/governance/source-01-reported.json
platform/examples/governance/source-02-transport.json
platform/examples/governance/source-03-wash.json
platform/examples/governance/source-04-sales.json
platform/examples/governance/source-05-stock.json
```

在 `platform/` 目录按
[可信数据接入说明](../platform/docs/可信数据接入说明.md#5-从零执行演示) 的
5.1—5.3 节登录并注册它们。演示配置对应：

```text
profile_id       trusted-five-flow
profile_version  2026.1
mine_id          M001
```

来源注册文件中的 `hmac_secret` 必须与独立设备/采集网关的同名来源密钥逐一
一致；该密钥不得配置给填报智能体。各系统只对齐 ID、版本和契约字段，不共享
注册表文件或数据库。生产部署应在注册前替换全部 `DEMO_ONLY_...` 密钥。

### 登记企业确认人

机器客户端环境变量只登记运输身份、企业和矿井范围。谁能代表企业确认报送，由
监管端自己的持久注册表决定：

```http
POST /v1/admin/external-confirmers
Cookie: <监管端登录会话>
X-CSRF-Token: <登录响应中的令牌>
Content-Type: application/json

{
  "registration_id": "ENT-001-operator-001-v1",
  "client_id": "enterprise-client-001",
  "enterprise_id": "ENT-001",
  "confirmer_id": "operator-001",
  "version": 1,
  "confirmer_name": "张三",
  "confirmer_roles": ["企业报送负责人"],
  "confirmation_methods": ["authenticated_click"],
  "active": true,
  "source_system": "regulator-confirmer-ledger",
  "record_id": "confirmer-case:ENT-001:operator-001"
}
```

同一 `client_id + enterprise_id + confirmer_id` 必须从版本 1 连续追加。改名或
调整角色时提交完整的下一版本；停用时同样追加下一版本并设 `active=false`。
记录不能原地覆盖或删除，完全相同的请求可以幂等重试。接入只按数据库当前版本
精确校验编号、姓名、角色和确认方式，并将命中记录 ID、版本、内容哈希写入批次
审计上下文。该接口要求 `config.manage` 权限和 CSRF；可用
`GET /v1/admin/external-confirmers` 查看完整版本历史。旧环境变量中的
`authorized_confirmers` 只会在尚无该确认人历史时迁移为版本 1，不参与接入判断。

### 登记监管事件查询快照

企业不能靠自报“无事件”绕过检查。管理员还要从监管侧事件台账查询精确矿井和
统计窗口，把完整结果（包括确实为空的结果）登记为不可变快照：

```http
POST /v1/admin/external-event-snapshots
Cookie: <监管端登录会话>
X-CSRF-Token: <登录响应中的令牌>
Content-Type: application/json

{
  "snapshot_id": "M001-20260727-event-query-001",
  "mine_id": "M001",
  "window_start": "2026-07-26T16:00:00Z",
  "window_end": "2026-07-27T16:00:00Z",
  "event_codes": [],
  "evidence_sha256": "<监管查询结果或导出材料的64位sha256>",
  "source_system": "regulator-event-ledger",
  "record_id": "query-result:M001:20260727"
}
```

企业草稿中 `approved_event_codes` 的值，以及该字段 provenance 的
`evidence_sha256`，必须和这一快照精确对应。平台按矿井、起止时间、排序后的完整
代码集合和证据摘要等值匹配；缺项、多项、窗口偏差、伪造空数组都会拒收。该接口
需要管理员的 `config.manage` 权限，快照只能幂等追加，不能覆盖或删除。可用
`GET /v1/admin/external-event-snapshots` 核对登记结果。

## 4. 启动企业智能体

在终端 B 安装企业端：

```bash
cd /path/to/coral/agent
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -e .
```

配置独立数据库、平台地址和运输身份：

```bash
export ENTERPRISE_AGENT_DB='./data/enterprise-agent.db'
export PLATFORM_BASE_URL='http://127.0.0.1:8080'
export PLATFORM_CLIENT_ID='enterprise-client-001'
export PLATFORM_TRANSPORT_HMAC_SECRET='DEMO_ONLY_change_transport_secret_32_chars'
enterprise-agent serve --host 127.0.0.1 --port 8090
```

`serve` 是常驻前台进程：启动成功会打印浏览器地址、数据库和平台配置状态，随后
终端不会回到 shell 提示符；没有新请求时也不会继续滚动输出，这不是卡死。保持
终端 B 运行，另开终端执行：

```bash
curl -fsS http://127.0.0.1:8090/api/v1/health
```

返回 `"status":"ok"` 才说明服务已就绪。`platform_configured:false` 表示企业端
没有读到完整的平台地址、客户端 ID 和运输密钥；此时仍可登录、建草稿和预检，但
正式提交必然失败。修改环境变量后必须停止并重新启动进程。

`PLATFORM_SUBMISSION_PATH` 和 `PLATFORM_CAPABILITIES_PATH` 使用默认值即可；若通过
反向代理改了外部路径，再显式设置：

```bash
export PLATFORM_SUBMISSION_PATH='/v1/enterprise-submissions'
export PLATFORM_CAPABILITIES_PATH='/v1/enterprise-submission-capabilities'
```

打开 <http://127.0.0.1:8090/>。未配置企业用户时可用仅限本机的
`demo / 123123123` 登录查看和编辑，但该临时账号不能确认或提交。正式账号通过
`enterprise-agent hash-password` 生成密码摘要，并写入密钥系统管理的
`ENTERPRISE_AGENT_USERS_JSON`。若监听非本机地址，CLI 会强制逐用户账号、
Secure Cookie，并要求部署在 HTTPS 反向代理后。

正式 HTTPS 反代还必须显式配置唯一的浏览器 origin，例如：

```bash
export ENTERPRISE_AGENT_SECURE_COOKIE=true
export ENTERPRISE_AGENT_PUBLIC_ORIGIN='https://report.enterprise.example'
```

反向代理传给应用的 `Host` 必须与该 origin 的 authority 精确一致；应用不会
信任 `X-Forwarded-*` 来绕过 Host/Origin 校验。完整 systemd、Nginx 和安全环境
文件模板见[企业端部署与运维](../agent/docs/部署与运维.md)。

若命令运行在远程服务器 `phoenix2`，浏览器里的 `127.0.0.1` 指向浏览器所在电脑，
并不指向服务器。推荐继续让服务只监听服务器回环地址，在本地电脑另开终端建立
SSH 隧道：

```bash
ssh -N -L 8090:127.0.0.1:8090 sevan@phoenix2
```

保持 SSH 命令运行，再在本地浏览器打开 <http://127.0.0.1:8090/>。若本地 8090
已被占用，可把左侧端口改为 18090：

```bash
ssh -N -L 18090:127.0.0.1:8090 sevan@phoenix2
```

此时打开 <http://127.0.0.1:18090/>。不要为了省略隧道直接监听 `0.0.0.0`；正式
远程部署必须配置逐用户账号，并通过 HTTPS 反向代理提供 Secure Cookie。

## 5. 完成一次报送

在企业智能体页面依次执行：

1. 新建草稿，填写企业 `ENT-001`、矿井 `M001`、窗口以及
   `trusted-five-flow / 2026.1`。
2. 从设备/采集网关导入带 `payload_sha256` 与 `signature` 的五个预签名观测；
   手工填写或修改观测会使来源签名失效，不能提交。
3. 补全 `regime_code`、`shift_code`、`season_code` 和 `maintenance` 四轴工况；
   已批准事件必须引用真实、可核查记录。
4. 从监管事件查询系统导入独立事件快照 JSON。快照必须与草稿矿井、起止时间
   精确一致，并包含 `event_codes`、监管证据 SHA-256、来源系统和记录号；查询
   结果为空也必须导入这一权威空集。普通生产报告里的空数组或手填事件不能替代。
5. 当前登录经办人对照原始台账逐条核对每一项观测并记录“已核对”。核对状态
   绑定观测编号、数值、单位、时间、来源摘要和签名；任一内容变化都会自动撤销。
6. 执行确定性预检并处理全部阻断项。
7. 由完成上述逐条核对的企业经办人明确确认。确认后任何字段修改都会使确认失效，
   必须重新预检和确认。
8. 提交。智能体先读取 capabilities，原样转发来源网关签名、构建契约信封，并给
   实际 HTTP body 加企业运输 HMAC；它不会也不能重新签来源观测。

平台验证客户端范围、时间/nonce、运输 HMAC、Schema、载荷摘要、字段来源、人工
确认、逐条来源签名、幂等键及监管注册表后返回回执。相同内容可按原提交号和幂等键
安全重试，但每次 HTTP 重试都会使用新的时间、nonce 和运输签名。

回执中的 `accepted` 和
`regulatory_outcome = not_determined_at_intake` 只表示接入处理成功，不表示数据
正常、真实、合法或合规。监管平台仍会独立执行物理、历史和时序算法，并由监管
人员复核；企业端预检和企业确认都不能替代监管认定。

## 6. 可选模型辅助

不设置任何模型变量时，规则导入、缺项追问、校验、确认和提交均可使用。需要候选
字段提取时，只在企业端进程环境中注入：

```bash
export DEEPSEEK_API_KEY='由企业密钥系统注入'
export DEEPSEEK_BASE_URL='https://api.deepseek.com'
export DEEPSEEK_MODEL='deepseek-v4-flash'
```

不要把真实值写入 `.env.example` 或报送内容。模型可用于候选字段提取，也可在
煤炭智能任务中选择本地确定性工具；自动规划会把任务、工具 schema 和脱敏限长的
工具结果发送给该第三方。若不允许业务摘要出域，不设置 Key 或在任务中选择
“仅确定性工具”。模型不能读取 HMAC 密钥、代替人工确认或自动提交；无效 JSON、
超时和模型故障均应失败关闭或降级到固定确定性工具组合。

## 7. 验证与排错

先分别运行独立测试：

```bash
cd /path/to/coral
python3 contracts/scripts/validate_contracts.py

cd platform
. .venv/bin/activate
python3 -m pytest

cd ../agent
. .venv/bin/activate
python3 -m pytest
```

常见问题：

- 启动命令“没有反应”：`serve` 本来就会常驻前台；不要反复启动，先在另一个
  终端请求 health。按 `Ctrl+C` 才会停止。
- `Address already in use`：已有进程占用端口。先执行
  `ss -ltnp | grep ':8090'` 核对；若正是所需服务就直接使用，否则明确停止旧
  进程，或通过 `--port 18090` 改用新端口。不要对不明 PID 使用强制终止。
- 服务器本机 health 正常但自己电脑打不开：使用上面的 SSH 隧道。浏览器不能
  直接访问远程服务器的 `127.0.0.1`。
- health 显示 `platform_configured:false`：三项
  `PLATFORM_BASE_URL`、`PLATFORM_CLIENT_ID`、
  `PLATFORM_TRANSPORT_HMAC_SECRET` 必须在启动企业进程的同一环境中同时存在。
- capabilities 无法访问：先确认监管进程、端口和
  `PLATFORM_BASE_URL`。
- HTTP 401：检查两端 `client_id`、运输密钥、系统 UTC 时间；网络重试不得复用
  nonce。服务端会有意使用统一认证错误，避免泄露客户端或密钥状态。
- HTTP 403：检查 `enterprise_id` 和 `mine_id` 是否在该客户端授权范围。
- HTTP 409：不要让同一提交号或幂等键指向不同内容；修改后创建新的提交。
- Schema/来源证明错误：按智能体的阻断问题补齐字段和 provenance，不能用模型
  编造缺失值。
- 来源或配置错误：确认监管端已注册相同 profile 版本和 source ID，来源有效期
  覆盖窗口，且设备/网关签名与监管端来源密钥匹配；智能体不保存该来源密钥。
- 修改后无法提交：修改会撤销旧人工确认，重新预检并确认即可。
- 平台停机或网络中断：企业端会把首次完整请求和失败状态落库；恢复平台后，对同一
  草稿使用原幂等键重试，不能另造报送时间或改用新键规避失败记录。
- 服务重启后数据不见：确认重启前后使用的是同一个
  `ENTERPRISE_AGENT_DB` 和同一个监管 `--state-directory`。相对路径按启动时的
  当前目录解析，运维环境建议使用绝对路径。
- 停止后仍提示端口占用：先等待数秒再用 `ss -ltnp` 核对监听 PID。正常
  `Ctrl+C`/`SIGTERM` 会关闭监听；若是其他会话启动的服务，应回到对应会话停止。

生产上线前还需完成 HTTPS、统一 IAM、密钥轮换、时钟同步、日志脱敏、设备侧
签名、备份恢复和监管授权流程；本地双进程演示不等同于生产安全部署。

完整自动化黑盒验收可直接运行：

```bash
cd /path/to/coral
python3 scripts/verify_two_process.py
```

它除正常报送外，还会验证端口占用快速失败、非安全远程监听被拒绝、演示账号无
确认/提交权限、普通报告不能冒充监管事件快照、权威空集证明、逐观测核对持久化、
监管配置缺失被拒、错误运输密钥被拒、重复提交幂等、平台停机后原请求可恢复重试、
双服务重启后数据仍在，以及退出后没有验收子进程残留。
