# 本地双系统运行（V2 导航）

> 2026-08-01 起，本页已替换原 V1 联调手册。旧版描述的
> `/v1/enterprise-submissions`、管理员可信来源登记和多算法写入口不属于当前默认
> 产品，请勿用于新部署。

当前本地运行严格只有两个软件：

```text
agent/                         platform/
一座矿一个企业智能体   V2    政府集中监管平台
人工导入或直采  ───────────>  唯一五量算法
风险解读与回复  <───────────  自动报告、留痕、领导只读大屏
```

`contracts/` 是中立协议文件，不是服务。独立 `edge-agent` 已退役；目录监听和受控
设备/API 接入由每矿自己的 Agent 承担。不同煤矿由不同所有者运营，必须使用不同
Agent 实例、数据库、账号、目录和密钥。

正式五量是风量、电量、火工品量、入井人员量和产量。底层以六个规范原子字段传输，
是因为火工品量分别保存雷管数量（`count`）、炸药质量（`kg`）等有单位子项；这些
子项不能相加，六原子字段也不表示“六量”。人员字段 `mine_entry_persons` 仅表示
统计范围内实际入井人次，必须为整数并按 `sum` 聚合。

## 当前操作入口

完整、可复制的安装、环境变量和双终端启动命令见：

- [V2 部署与运行](V2部署与运行.md#4-本机完整联调)；
- [V2 验收清单](V2验收清单.md)；
- [V2 双系统目标架构](V2双系统目标架构.md)；
- [企业智能体说明](../agent/README.md)；
- [政府平台说明](../platform/README.md)。

确认命令面：

```bash
cd /home/sevan/coral/platform
PYTHONPATH=src python3 -m mineguard --help

cd /home/sevan/coral/agent
PYTHONPATH=src python3 -m enterprise_agent --help
```

政府端启动入口为：

```bash
mineguard serve --host 127.0.0.1 --port 8080 \
  --state-directory .mineguard-v2
```

企业端启动入口为：

```bash
enterprise-agent serve --host 127.0.0.1 --port 8090
```

两端的矿井身份、两把不同 HMAC 密钥和政府逐矿注册表必须先按主部署手册配置。只启动
进程但未配置 V2 客户端，不等于业务就绪。

本机默认演示凭据为：

| 产品 | 账号 | 密码 | 限制 |
|---|---|---|---|
| 政府 Platform | `admin` | `123123123` | 仅全新回环演示状态目录 |
| 企业 Agent | `demo` | `123123123` | 待换密，不能确认或报送 |

完整报送需为 Agent 配置具名 `confirm + submit` 账号。生产必须更换默认密码并通过
HTTPS 反向代理访问。

健康检查：

```bash
curl -fsS http://127.0.0.1:8080/healthz
curl -fsS http://127.0.0.1:8080/readyz
curl -fsS http://127.0.0.1:8090/api/v1/health
```

人工导入和直采都是合法来源，只留采集方式轨迹，算法不按来源分配信任、权重或阈值。
企业解释不能消除风险；只有更高修订版重新通过政府同一算法，才能记录
`cleared_by_reanalysis`。
