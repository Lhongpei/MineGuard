该历史阶段采用两个独立软件：

1. `agent/`：一座煤矿一个企业智能体。不同煤矿属于不同经营主体，不共享实例、
   数据库、账号、目录、会话或密钥；负责人工导入/直采、规范化、企业确认、可靠报送、
   风险解读和人工确认后的回复。
2. `platform/`：政府监管平台。自动验签接收、运行当时的五量算法、发送报告、记录企业
   回复和修订复算；领导业务界面只读，不代企业操作。

`contracts/` 只提供中立 V2 Schema、OpenAPI 和签名规范，不运行服务。原
`edge-agent` 中有价值的固定目录监听、稳定文件识别、哈希去重、隔离和断网续传能力，
已经归入每矿 Agent。

## 历史 V2 方案落实口径

| 建设要求 | 当前 V2 落实方式 |
|---|---|
| 企业获得并上报五量 | Agent 人工导入或受控直采，规范化后由具名人员确认 |
| 五量字段 | 五类为风量、电量、火工品量、入井人员量、产量；底层六个原子字段中雷管数量与炸药质量均归属火工品量，不构成“六量” |
| 单矿核查 | Platform 唯一五量引擎自动完成确定性、历史、时序和求解分析 |
| 多矿比较 | 至少三座可比矿、每矿等权的匿名区间，不泄露他矿明细 |
| 风险反馈 | 企业主动拉取签名报告，在本矿 Agent 内解读并形成回复草稿 |
| 风险解除 | 文字解释只留痕；更高修订版通过同一算法后才可解除 |
| 监管操作 | 政府业务界面只读，自动收件、分析、报告和追加留痕 |
| 实时展示 | 领导大屏按 `as_of` 和轮询周期展示辖区及单矿状态 |
| 采集来源 | 人工和直采同等合法，不按来源方式降权或提高阈值 |

求解器与既有时序方法都位于政府唯一算法内部。HiGHS 加权 L1 计算满足日报—班次等
硬约束、并接近本矿历史/匿名同类矿软区间所需的最小标准化联合调整；MCS 定位最少
需要复核的日期、指标和冲突组。它们不输出“真实产量”，也不把历史相关性当成物理
定律。
